# APIM-003 API + MCP Blueprint Compiler for Spring MVP最小要件定義書 v0.1

## 1. 文書概要

### 1.1 文書目的

本書は、**API + MCP Blueprint Compiler for Spring** の初期MVPに必要な最小要件を定義する文書である。

APIM-001「API + MCP Blueprint Compiler for Spring 立ち上げ方針書 v0.1」では、本プロダクトを、自然言語の業務要件から Spring 向け REST API 設計と MCP 設計を同時に生成する設計支援Webツールとして定義した。

本書では、その方針を受けて、初期MVPで実装・検証すべき範囲を以下の観点で具体化する。

- MVPの目的
- 想定ユーザー
- ユースケース
- 入力仕様
- 出力仕様
- 画面要件
- 機能要件
- 非機能要件
- セキュリティ・承認・監査ログ要件
- 対象外範囲
- 受け入れ条件
- 次フェーズへの引き継ぎ事項

### 1.2 文書位置づけ

| 項目 | 内容 |
|---|---|
| 文書ID | APIM-003 |
| 文書名 | API + MCP Blueprint Compiler for Spring MVP最小要件定義書 v0.1 |

| 後続実装担当候補 | Codex |

### 1.3 本書の基本判断

本MVPは、**完全なアプリケーション生成ツールではなく、設計成果物生成ツール**として成立させる。

本プロダクト自体は、将来的に Spring Boot Web アプリとして実装する想定である。  
ただし、本プロダクトが出力する成果物としては、完全動作する Spring Boot アプリケーションや MCP サーバーを生成しない。

## 2. プロダクト概要

### 2.1 製品名

    API + MCP Blueprint Compiler for Spring

### 2.2 短縮名

    APIM for Spring

### 2.3 製品カテゴリ

    Spring向け API / MCP 設計生成支援Webツール

### 2.4 基本コンセプト

APIM for Spring は、自然言語で記述された業務要件から、以下を同時生成する。

- REST API設計
- MCP tools / resources / prompts 設計
- API / MCP対応表
- Spring Controller雛形
- セキュリティ・承認・監査ログ設計メモ
- AI実装指示書

これにより、Springシステム開発における「業務要件 → API設計 → MCP設計 → 実装指示」の初期設計工程を支援する。

### 2.5 Q-Scout for Spring との差別化

| 観点 | APIM for Spring | Q-Scout for Spring |
|---|---|---|
| 主目的 | 新規設計生成 | 既存システム診断 |
| 入力 | 業務要件テキスト | Springプロジェクト |
| 出力 | API/MCP設計書、Controller雛形、AI実装指示書 | 診断レポート、AI改善相談用Markdown |
| 利用タイミング | 実装前 | 実装後・レビュー時 |
| 主な価値 | 設計高速化・AI時代の公開境界整理 | 品質可視化・改善支援 |

本MVPでは、診断・解析・スコアリング機能は扱わない。

## 3. MVP目的

### 3.1 MVPの目的

初期MVPの目的は、ユーザーが自然言語で業務要件を入力し、Spring向けの API 設計と MCP 設計を一体的に確認できる Markdown 成果物を生成できる状態を作ることである。

### 3.2 MVPで検証したい仮説

| 仮説ID | 仮説 |
|---|---|
| H-001 | 業務要件から REST API と MCP tool を同時に整理することで、設計初期の抜け漏れを減らせる |
| H-002 | API / MCP 対応表を生成することで、人間向け機能入口とAI向け操作入口の関係を説明しやすくなる |
| H-003 | 書き込み操作・削除操作・外部送信操作に承認要否と監査ログ観点を付与することで、AI連携設計の安全性を高められる |
| H-004 | Spring Controller 雛形とAI実装指示書を出力することで、Codex等への後続実装依頼に接続しやすくなる |
| H-005 | 完全実装生成ではなく設計成果物生成に絞ることで、MVPとして短期間に成立させられる |

### 3.3 MVPの成功状態

初期MVPの成功状態は以下である。

1. ユーザーが業務要件を入力できる。
2. 入力内容から API 設計サマリーが生成される。
3. RESTエンドポイント候補が生成される。
4. MCP tools / resources / prompts 候補が生成される。
5. API / MCP 対応表が生成される。
6. Spring Controller 雛形が生成される。
7. セキュリティ・承認・監査ログ注意点が生成される。
8. Markdown設計書としてコピーまたは保存できる。
9. AI実装指示書として後続AIへ渡せる形式で出力できる。
10. 完全動作するSpringアプリやMCPサーバーを生成しないという制約が守られている。

## 4. 想定ユーザー

### 4.1 主ユーザー

| ユーザー種別 | 利用目的 |
|---|---|
| 個人開発者 | 業務要件からSpring API設計案を素早く作る |
| Spring学習者 | 業務要件とREST API設計の対応を学ぶ |
| 設計担当者 | APIとAI向けMCP入口の関係を整理する |
| AI活用開発者 | Codex等へ渡す実装指示書を作る |
| ポートフォリオ閲覧者 | API設計・MCP設計・AI実装連携の発想を確認する |

### 4.2 初期MVPの主要利用者

初期MVPでは、以下を最優先ユーザーとする。

    Spring Bootで業務Webアプリを作りたい個人開発者または設計担当者

理由:

- 入力が自然言語の業務要件であるため、専門的なコード解析環境を必要としない。
- API設計とMCP設計の関係を見せるポートフォリオ価値が高い。
- Controller雛形とAI実装指示書により、後続のCodex実装へ接続しやすい。

### 4.3 MVPで優先しないユーザー

初期MVPでは、以下のユーザーは優先対象外とする。

- 大規模エンタープライズAPI設計者
- OpenAPI完全準拠を求めるAPI設計チーム
- 実運用MCPサーバーを即時生成したいユーザー
- 認証認可コードの自動生成を求めるユーザー
- DB設計・Entity設計まで自動生成したいユーザー

| S-007 | DTO候補生成 | Request / Response DTO候補を生成する |
| S-008 | Controller雛形生成 | Spring Controller雛形を生成する |

### 6.2 MVPで実施しないこと

初期MVPで実施しないことは以下である。

| ID | 対象外項目 | 理由 |
|---|---|---|
| O-001 | 完全動作するSpring Bootアプリ生成 | 範囲過大化を避けるため |
| O-002 | 完全動作するMCPサーバー生成 | 初期MVPでは設計案生成に限定するため |
| O-003 | Entity / Repository / Service完全実装 | 実装生成ではなく設計支援が目的のため |
| O-004 | DB設計・マイグレーション生成 | ドメインモデリングが別フェーズになるため |
| O-005 | OpenAPI YAML完全準拠生成 | MVPではエンドポイント表に限定するため |
| O-006 | 認証認可コード自動生成 | セキュリティリスクが高く詳細設計が必要なため |
| O-007 | 外部LLM API連携必須化 | MVPの実装難度を下げるため |
| O-008 | GitHub自動PR作成 | 生成成果物確認後に人間判断を挟むため |
| O-009 | 本番デプロイ | 初期MVPではローカル実行・設計検証を優先するため |
| O-010 | 複数プロジェクト横断設計 | 初期入力を単一業務ドメインに限定するため |

### 6.3 境界条件

本MVPでは、以下の境界条件を設ける。

- 入力は単一業務ドメインを前提とする。
- 出力はMarkdownと画面表示を中心とする。
- 生成コードはController雛形に限定する。
- MCPは定義案生成に限定する。
- セキュリティは注意点・設計メモとして生成し、実装コードは生成しない。
- AI実装指示書は生成するが、AI実装そのものは実行しない。

### 7.1 入力項目

| 項目ID | 項目 | 必須 | 形式 | 上限 | 説明 |

| IN-009 | 監査ログが必要な操作 | 任意 | 複数行テキスト | 2,000文字 | 証跡を残すべき操作 |

| IN-012 | 出力言語 | 任意 | 選択 | - | 日本語 / 英語 |

### 7.2 必須入力の初期判断

初期MVPでは、以下を必須とする。

- 業務要件
- 対象ドメイン
- ユーザー種別
- 必要な操作
- AIアシスタントに許可したい操作

理由:

- API設計には業務要件・ドメイン・操作が必要である。
- MCP設計にはAIに許可する操作の明示が必要である。
- ユーザー種別がないと、認可・承認・監査ログ観点を生成しづらい。

### 7.3 入力例

    業務要件:
    社内の営業担当が顧客情報を検索し、問い合わせ履歴を確認できる。
    管理者は顧客情報を登録・更新できる。
    AIアシスタントには顧客検索と問い合わせ履歴の要約を許可したい。
    顧客情報の更新はAIが直接実行せず、変更案を作成して人間承認後に反映する。

    対象ドメイン:
    顧客管理

    ユーザー種別:
    - 営業担当
    - 管理者
    - AIアシスタント

    必要な操作:
    - 顧客検索
    - 顧客詳細取得
    - 顧客登録
    - 顧客更新
    - 問い合わせ履歴取得
    - 問い合わせ履歴要約

    AIアシスタントに許可したい操作:
    - 顧客検索
    - 顧客詳細参照
    - 問い合わせ履歴要約
    - 顧客更新案の作成

    承認必須操作:
    - 顧客情報更新
    - 顧客削除

### 8.4 Controller雛形の制約

Controller雛形は、以下の制約を守る。

- `@RestController` を含める。
- `@RequestMapping` を含める。
- API候補に対応するメソッドを含める。
- DTO名を候補として示す。
- Service呼び出し位置をコメントで示す。
- 認可・承認・監査ログのコメントを含める。
- 完全にコンパイル可能であることは必須としない。
- Entity / Repository / DBアクセスコードを含めない。

### 8.5 MCP出力の制約

MCP出力は、以下の制約を守る。

- tools / resources / prompts の定義案として出力する。
- 完全動作するMCPサーバーコードは出力しない。
- toolごとに操作区分を付与する。
- toolごとにAI実行可否を付与する。
- 書き込み系toolには承認要否を付与する。
- 監査ログ要否を付与する。
- 危険操作には人間確認を推奨する。

## 11. 生成ロジック要件

### 11.1 初期生成方式

初期MVPでは、生成方式は以下のいずれか、または組み合わせとする。

| 方式 | 内容 | 初期採用 |
|---|---|---|
| ルールベース生成 | 入力された操作名やドメインからテンプレートに沿って生成 | 採用候補 |
| テンプレートベース生成 | 固定のMarkdownテンプレートへ入力値を埋め込む | 採用候補 |
| 外部LLM連携 | LLM APIを利用して設計案を生成 | 初期必須ではない |
| ハイブリッド生成 | ルールベース + LLM補助 | 将来候補 |

初期MVPでは、外部LLM API連携を必須としない。

理由:

- APIキー管理が必要になる。
- コストと外部依存が増える。
- 生成結果の再現性が下がる。
- ローカル・ポートフォリオ用途のMVPとしては、まずテンプレートベースで価値検証できる。

### 11.2 API候補生成ルール

初期MVPでは、必要な操作に含まれる語から、以下のようにAPI候補を生成する。

| 操作語 | HTTPメソッド候補 | パス候補 |
|---|---|---|
| 検索 / 一覧 | GET | `/api/{domain}` |
| 詳細取得 / 参照 | GET | `/api/{domain}/{id}` |
| 登録 / 作成 | POST | `/api/{domain}` |
| 更新 | PUT / PATCH | `/api/{domain}/{id}` |
| 削除 | DELETE | `/api/{domain}/{id}` |
| 承認依頼 | POST | `/api/{domain}/{id}/approval-requests` |
| 承認 | POST | `/api/approval-requests/{id}/approve` |
| 却下 | POST | `/api/approval-requests/{id}/reject` |

### 11.3 MCP tool生成ルール

MCP tool は、操作種別に応じて以下の命名を基本とする。

| 操作 | tool名候補 |
|---|---|
| 検索 | `search{Domain}` |
| 詳細取得 | `get{Domain}Detail` |
| 要約 | `summarize{Domain}` |
| 登録 | `create{Domain}Draft` |
| 更新 | `propose{Domain}Update` |
| 削除 | `request{Domain}DeletionApproval` |
| 承認依頼 | `requestApprovalFor{Domain}` |

### 11.4 AI実行可否判定ルール

| 操作区分 | 初期判定 |
|---|---|
| 読み取り | AI実行可 |
| 検索 | AI実行可 |
| 要約 | AI実行可。ただし機密情報注意 |
| 登録 | 下書き作成または承認後実行 |
| 更新 | 提案のみまたは承認後実行 |
| 削除 | 原則AI実行不可 / 承認必須 |
| 外部送信 | 原則承認必須 |
| 権限変更 | AI実行不可 / 承認必須 |

### 11.5 セキュリティ注意点生成ルール

以下の操作を検出した場合、警告または注意点を生成する。

- 削除
- 更新
- 外部送信
- 権限変更
- 個人情報参照
- 機密情報参照
- 金銭・契約・顧客影響操作
- AIによる自動実行

## 13. データ管理要件

### 13.1 永続化方針

初期MVPでは、入力内容および生成結果をサーバー側に永続保存しない。

理由:

- 個人情報や機密情報を含む業務要件が入力される可能性がある。
- 初期MVPでは設計支援と表示・コピー・ダウンロードに集中する。
- DB設計をMVPから除外し、実装範囲を抑える。

### 13.2 一時保持

生成結果は、以下のいずれかで扱う。

| 方式 | 内容 | 初期採用 |
|---|---|---|
| リクエストスコープ | 生成直後の画面表示のみ | 採用候補 |
| セッション保持 | ブラウザセッション中のみ保持 | 採用候補 |
| 一時ファイル | ダウンロード用に一時保存 | 必要に応じて |
| DB保存 | 履歴管理 | 初期対象外 |

### 13.3 生成ファイル名

| 成果物 | ファイル名 |
|---|---|
| Markdown設計書 | `api-mcp-blueprint.md` |
| AI実装指示書 | `implementation-instructions.md` |

## 20. 最終結論

APIM for Spring の初期MVPは、**自然言語の業務要件から、API設計とMCP設計を同時に生成する設計支援Webツール**として成立させる。

初期MVPでは、完全動作するMCPサーバーやSpring Bootアプリケーションの自動生成には踏み込まない。

生成対象は、以下に限定する。

- API設計サマリー
- RESTエンドポイント一覧
- DTO候補
- Spring Controller雛形
- MCP tools / resources / prompts 定義案
- API / MCP tool 対応表
- セキュリティ・承認・監査ログ注意点
- Markdown設計書
- AI実装指示書

本要件定義により、次フェーズである APIM-004 基本設計書の作成に進む準備が整う。

以上を、APIM-003 API + MCP Blueprint Compiler for Spring MVP最小要件定義書 v0.1 とする。
