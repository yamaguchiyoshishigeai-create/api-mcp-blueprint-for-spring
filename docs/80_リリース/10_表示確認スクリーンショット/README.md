# 表示確認スクリーンショット

## 1. 目的

本ディレクトリは、APIM for Spring のREADME掲載、公開後確認、ポートフォリオ説明、面談時説明に使用する表示確認スクリーンショットを管理する。

スクリーンショットは装飾目的ではなく、README閲覧だけでAPIMの主要画面、価値、生成導線、成果物イメージが分かるようにするための確認資料として扱う。

## 2. 配置方針

保存先は以下とする。

```text
docs/80_リリース/10_表示確認スクリーンショット/
```

本配置は、portfolioリポジトリの表示確認スクリーンショット配置方針と揃える。APIM本体では、`docs/` 配下が企画、要件、設計、実装、リリース、改善タスク管理を保持する正本領域であるため、README掲載用の公開確認画像も `80_リリース` 配下で管理する。

## 3. 推奨ファイル名

| ファイル名 | 対象画面 | 確認観点 |
|---|---|---|
| `apim-01-top.png` | トップ画面 | 製品概要、対象利用者、主要CTAが伝わること |
| `apim-02-input.png` | Step1 入力画面 | 自由文入力、チェック式入力、業務要件入力の導線が伝わること |
| `apim-03-external-ai-prompt.png` | 外部AI投入用プロンプト生成画面 | 外部AIへ自動送信せず、手動投入用プロンプトを生成する導線であることが伝わること |
| `apim-04-result-summary.png` | Step4 結果画面 | 生成成果物の確認ポイント、API設計、MCP設計、セキュリティ・監査、実装引き継ぎが把握できること |
| `apim-05-preview.png` | プレビュー画面 | API&MCP設計書またはAI実装指示書の成果物イメージが伝わること |

## 4. 取得方針

- Render公開環境または現行main相当のローカル起動環境から取得する。
- ブラウザ枠は原則含めない。
- 主要な訴求箇所が読める範囲で取得する。
- 個人情報、実企業名、顧客名、内部システム名、APIキー、認証情報、秘密情報を含めない。
- 画面上の文言が現行README、Help、Render公開後確認記録と矛盾しないことを確認する。
- スマホ幅画像を追加する場合は、ファイル名末尾に `-mobile` を付ける。

## 5. README掲載方針

`README.md` には、主要画面を過剰に増やさず、APIMの価値と導線が伝わる範囲で掲載する。

推奨掲載順は以下とする。

1. トップ画面
2. Step1 入力画面
3. 外部AI投入用プロンプト生成画面
4. Step4 結果画面
5. プレビュー画面

READMEからの参照例:

```markdown
![APIM top screen](docs/80_リリース/10_表示確認スクリーンショット/apim-01-top.png)
```

## 6. TSK-074完了条件との対応

TSK-074の完了条件は以下である。

- README閲覧だけで主要画面と価値が把握できる。
- 画像リンク切れがない。
- スクリーンショットが現行UIと一致している。

本ディレクトリへ画像を配置し、READMEから相対パスで参照したうえで、リンク切れ確認と現行UI一致確認を行うことで完了条件を満たす。
