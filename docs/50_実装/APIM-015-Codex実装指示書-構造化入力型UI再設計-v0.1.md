# APIM-015 Codex実装指示書 構造化入力型UI再設計 v0.1

## 1. 作業ID

TSK-015

## 2. 作業目的

APIM for Spring の入力画面を、自由文意味理解AIと誤認されにくい構造化入力型へ再設計する。

現行APIMはLLMを内包しない静的ルールベースMVPであるため、ユーザーが選択した要素からAPI/MCP設計候補が生成されることをUI上で明確にする。

## 3. 重要方針

現行のAI風自由文入力様式は削除しない。

ただし、主導線としては表示しない、または折りたたみ・将来拡張用セクションとして扱う。

将来LLM抽出レイヤーを追加する際、現行自由文入力様式を再利用できるようにする。

## 4. 実装対象

### 4.1 入力画面

`src/main/resources/templates/index.html` を中心に修正する。

以下を構造化入力として表示する。

- 対象ドメイン
- 利用者種別
- 必要操作
- AIに許可する操作
- AIに禁止する操作
- 読み取り専用操作
- 書き込み操作
- 承認必須操作
- 監査ログ必須操作
- 想定認証方式
- 想定利用者
- 出力言語

必要操作、AIに許可する操作、AIに禁止する操作、承認必須操作、監査ログ必須操作はチェックボックスまたは複数選択式を使用する。

対象ドメインはプリセット選択と任意入力を併用できるようにする。

### 4.2 既存モデル互換

既存の `BlueprintInput` を大きく壊さない。

選択式UIで選んだ値は、既存の以下フィールドへ送信またはController側で集約する。

- `requiredOperations`
- `allowedAiOperations`
- `readOnlyOperations`
- `writeOperations`
- `approvalRequiredOperations`
- `auditLogRequiredOperations`

既存Generatorは原則維持する。

### 4.3 現行自由文入力様式の保持

現在の自由文入力欄群は、将来LLM抽出レイヤー用として保持する。

保持方法は次のいずれかとする。

- `index.html` 内に非表示セクションとして残す。
- Thymeleaf fragmentとして分離し、通常画面では表示しない。
- コメントではなく実際のテンプレートとして残し、将来復帰しやすくする。

単に削除してはならない。

### 4.4 文言修正

画面上の説明文は、以下の趣旨へ修正する。

- APIMは自由文意味理解AIではない。
- 選択された構造化要素からAPI/MCP設計候補を生成する。
- 自由文欄は補足情報であり、現時点では意味解析対象ではない。

## 5. 非対象

以下は実装しない。

- 外部LLM API連携
- LLMプロンプト設計
- 自由文から構造化入力を自動抽出する処理
- DB永続化
- Spring Security本格実装
- MCPサーバー実装
- OpenAPI完全生成

## 6. テスト要件

既存テストは全て成功させる。

必要に応じて、以下を追加または更新する。

- Controllerのフォーム送信テスト
- 代表的なチェックボックス選択から既存Generatorが期待通り操作種別を検出するテスト
- 現行自由文様式が削除されていないことを確認できる軽量テストまたはテンプレート確認

## 7. 手動確認観点

ローカルで以下を確認する。

- `/` にアクセスすると、構造化入力型の画面が表示される。
- 自由文意味理解AIではないことが画面文言から分かる。
- サンプル入力ボタンにより、構造化入力項目が埋まる。
- 設計候補生成後、既存の結果画面、Markdownプレビュー、AI実装指示書プレビューが利用できる。
- 現行自由文入力様式が削除されていない。

## 8. 完了条件

- UIの主導線が構造化入力型になっている。
- ユーザーが自由文意味理解AIと誤認しにくい説明文になっている。
- 既存Generatorと回帰テストが維持されている。
- 現行自由文入力様式が将来LLM抽出レイヤー用に保持されている。
- `mvnw.cmd test` またはCI上のMaven Wrapper testが成功している。
