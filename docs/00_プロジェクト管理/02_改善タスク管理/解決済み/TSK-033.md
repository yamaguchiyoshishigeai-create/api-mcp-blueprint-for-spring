## 背景

複数ドメイン入力を `targetDomain` の単一文字列として扱うだけでは、主ドメインAPI、関連ドメイン参照API、横断操作の境界が曖昧になる。

TSK-031で正規化レイヤが導入され、TSK-032で生成成果物上のドメイン境界表示が追加されたため、TSK-033ではAPI Generatorの出力を主ドメイン・関連ドメインの境界を意識した候補生成へ拡張した。

## 最小実装境界

TSK-033では、API設計生成において、主ドメインAPI、関連ドメイン参照API、ドメイン別Controller候補、ドメイン別DTO候補が確認できる出力へ拡張する範囲に限定した。

## TSK-033で実施したこと

- API Generatorを正規化済み入力に対応させ、複数ドメイン時に主ドメインAPI候補と関連ドメイン参照API候補を分けて生成するようにした。
- 関連ドメインは参照一覧・参照詳細のGET候補に限定し、主ドメインと同等の作成・更新・削除候補は生成しないようにした。
- Controller候補とDTO候補に、主ドメインと関連ドメイン参照の境界が分かる候補を追加した。
- 旧入力 `targetDomain` のみ、または単一ドメイン入力で `relatedDomains` が空になる場合は、既存の生成経路を使い続けるようにした。
- `ApiEndpointCandidate` の既存コンストラクタ互換を維持し、既存テスト・MCP Generatorテストの入力を壊さないようにした。
- Codex Review P2指摘に対応し、`ControllerSkeleton.sourceCode` が複数のpackage/import付きJavaソースを連結しないよう修正した。
- 表示追加と互換維持に関するテストを追加・更新した。
