# TSK-048 CIポーリング終了条件固定方針を明文化する

## 状態

解決済み

## 優先度

High

## 主担当候補

ChatGPT(リポジトリ編集)

## 関連PR

- PR #92: TSK-048 CIポーリング終了条件固定方針を明文化する

## 背景

既存の待ちフェーズ運用方針では、GitHub Actions等のCI完了待ち、PR mergeability確定待ち、外部処理完了待ちにおいて、ChatGPTが同一応答ターン内で短時間ポーリングを行うことを定めていた。

しかし、`queued` / `in_progress` のまま数回確認しただけで「長引いている」と判断して応答を区切る余地が残っていた。

この問題を防ぐため、`queued` / `in_progress` は終了条件ではないこと、全Jobのsuccess / failure / cancelled / timed_out / 取得不能 / ユーザー割り込み / 異常長時間化のいずれかまで短時間ポーリングを継続することを明文化した。

## 対応結果

1. `CIポーリング終了条件固定方針.md` を横断運用規程として追加した。
2. `queued` / `in_progress` が終了条件ではないことを明文化した。
3. ポーリング継続条件と終了条件を表で整理した。
4. 異常長時間化の例外条件を限定した。
5. CI success後の `CI_GREEN` 扱いと、merge等の後続アクションの分離を明文化した。

## 実施しなかったこと

- 実装コード変更。
- テストコード変更。
- CI workflow変更。
- merge判断ルールの弱体化。
- `queued` / `in_progress` を終了条件として扱う余地を残すこと。
- 他リポジトリへの横展開。

## 完了条件確認

- `CIポーリング終了条件固定方針.md` が追加されている。
- `queued` / `in_progress` が終了条件ではないことが明記されている。
- success / failure / cancelled / timed_out / 取得不能 / ユーザー割り込み / 異常長時間化の終了条件が明記されている。
- 異常長時間化の扱いが限定されている。
- PR #92はCI success確認後にmainへmerge済み。
- merge後のremote branch cleanupとローカルpruneも完了済み。
