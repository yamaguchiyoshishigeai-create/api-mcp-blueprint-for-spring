## 背景

PR #108 の確認時に、ChatGPTが `CI success / mergeable true / scope内 / 未反映事項なし` を確認していたにもかかわらず、mergeをユーザー(人)作業として扱って停止した。

一方、現行運用では、CI完了待ちやmerge後cleanupは自動継続対象として扱われており、通常PRにおけるmerge判断までChatGPT(リポジトリ編集)で実施できるよう整理する必要があった。

現行文書には、ユーザー(人)の担当に `merge判断` が含まれる記述と、PR確認・CI確認・merge判断をChatGPT側で行う前提の記述が併存していたため、運用上の矛盾を解消した。

## 目的

通常PRについて、以下の条件を満たす場合はChatGPT(リポジトリ編集)がmergeまで進められることを明文化する。

- CIが終了条件まで `success` である。
- PRが `mergeable` である。
- 変更内容が事前合意スコープ内である。
- 要求仕様、指定文言、実装方針、テスト期待値、運用規則を弱めていない。
- 未反映事項、CI未確認、PR未作成、main未反映を完了扱いしていない。
- 外部サービス作成、公開判断、費用影響、秘密情報、破壊的変更、主観判断を伴わない。

## 実施内容

1. `docs/00_プロジェクト管理/05_横断運用規程/通常PR自動merge方針.md` を追加した。
   - ChatGPT(リポジトリ編集)が通常PRを自動mergeできる条件を定義した。
   - ユーザー(人)判断へ戻す条件を定義した。
   - merge後cleanup / local sync / prune確認を完了状態に含めることを明記した。
2. `docs/00_プロジェクト管理/05_横断運用規程/00_運用ルール索引と実行ゲート.md` を更新した。
   - ユーザー(人)の担当範囲から通常PRのmerge判断を無条件に含める表現を見直した。
   - ChatGPT(リポジトリ編集)の担当範囲へ通常PRのmerge判断とmerge実行を追加した。
   - PR / CI / mergeゲートを通常PR自動merge方針へ接続した。
3. `docs/00_プロジェクト管理/05_横断運用規程/Codex投入前ハンドオフゲート方針.md` を更新した。
   - PR確認・CI確認・通常PRのmerge判断をChatGPT(リポジトリ編集)担当として整理した。
   - merge後ブランチ削除・local sync・prune確認をChatGPT / ChatExec2 / ユーザー(人)の組み合わせで扱う表現へ補正した。

## 実施しないこと

- すべてのPRを無条件に自動mergeすること。
- CI未完了またはin_progress状態でmergeすること。
- failure / cancelled / timed_out / action_required をsuccess相当として扱うこと。
- 要求仕様やテスト期待値を弱めてmerge条件を満たしたことにすること。
- merge後cleanup / local syncを省略すること。
- `chatgpt-ops-rules` 側TSK-009の実装。
