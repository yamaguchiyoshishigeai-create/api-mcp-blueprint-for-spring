# TSK-023 待ちフェーズの短時間ポーリングとフォローアップ入力許容ルールを明文化する

- ID: TSK-023
- 件名: 待ちフェーズの短時間ポーリングとフォローアップ入力許容ルールを明文化する
- 状態: 解決済み
- 優先度: High
- 主担当候補: ChatGPT(リポジトリ編集)

## 背景

GitHub ActionsのCI完了待ちやPRのmergeability確定待ちでは、ユーザーが都度「現況確認してください」と問い合わせる運用になりやすい。

この方式では、待ちフェーズのたびにユーザー側の入力負担が増え、作業の連続性も損なわれる。

## 課題

ChatGPTは一度応答を返した後にバックグラウンドで常駐監視し続けることは前提にできない。

一方で、同一応答ターン内であれば短時間のポーリング確認を行い、CI成功時のmergeや失敗時のログ確認へ自動的に進められる。

また、ポーリング中であっても、ユーザーが追加指示、補足、停止、方針変更などを途中入力できる前提を明文化する必要がある。

## 対応内容

改善タスク課題一覧に「待ちフェーズ運用方針」を追加した。

主なルールは以下である。

- CI完了待ち、PR mergeability確定待ち、外部処理完了待ちでは、原則としてChatGPTが同一応答ターン内で短時間ポーリングを行う。
- 短時間ポーリング中も、ユーザーのフォローアップ入力を可能なものとして扱う。
- ユーザー入力があった場合は、直近の自動継続よりユーザー入力を優先する。
- successの場合は、合意済み範囲で次工程へ自動進行する。
- failureの場合は、失敗ログ確認、原因切り分け、最小修正方針提示、または修正へ進む。
- 長時間化した場合のみ、未完了状態と再開コマンド・PR番号等を明示して一旦報告する。
- 応答後のバックグラウンド常駐監視は前提にしない。

## 完了条件

- 待ちフェーズの標準運用が台帳上に明文化されている。
- ポーリング中のユーザーフォローアップ入力許容が明記されている。
- 成功時・失敗時・長時間化時の分岐が定義されている。
