## 背景

複数システム・複数ドメイン入力を扱う場合、生成されるMarkdown設計書とAI実装指示書に、対象システム種別、主ドメイン、関連ドメインの境界が表示されていないと、後続実装時に責務境界が曖昧になる。

TSK-031で `NormalizedBlueprintInput` と正規化レイヤが導入されたため、TSK-032ではその正規化済み情報を生成成果物上に表示できる状態へ進めた。

## 最小実装境界

TSK-032では、Markdown設計書とAI実装指示書に、対象システム種別、主ドメイン、関連ドメイン、正規化後ドメイン一覧が確認できる入力サマリーを追加する範囲に限定した。

## TSK-032で実施したこと

- Markdown設計書の入力要件サマリーへ対象システム種別、主ドメイン、関連ドメイン、正規化後ドメイン一覧を追加した。
- AI実装指示書へ主ドメインと関連ドメインの実装境界に関する注意を追加した。
- `BlueprintGenerationService` で取得済みの `NormalizedBlueprintInput` を Markdown設計書 / AI実装指示書 Generator へ渡すようにした。
- Generator単体の既存呼び出し互換として、従来の `generate(BlueprintInput, BlueprintResult)` を残し、必要時のみ内部で正規化して新しい生成処理へ委譲するようにした。
- 旧入力 `targetDomain` のみの場合も、主ドメインと正規化後ドメイン一覧へ反映され、関連ドメインは `なし` として表示されるようにした。
- 表示追加に関するテストを追加・更新した。

## TSK-032で実施しなかったこと

- API Generatorの複数ドメイン対応。
- MCP Generatorの複数ドメイン対応。
- Controller候補のドメイン別分割。
- DTO候補のドメイン別分割。
- tool / resource / prompt 候補のドメイン別分割。
- ドメインごとの完全な生成成果物分解。
