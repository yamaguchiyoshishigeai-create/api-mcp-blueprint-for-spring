# TSK-028 順次タスクmergeゲートを標準化する

- ID: TSK-028
- 件名: 順次タスクmergeゲートを標準化する
- 状態: 解決済み
- 優先度: High
- 主担当: ChatGPT(リポジトリ編集)
- 関連ルール: `docs/00_プロジェクト管理/02_改善タスク管理/改善タスク課題一覧.md`

## 背景

過去に、前タスクがmainへmergeされる前に後続タスクへ着手し、タスク起点やPR状態が不整合になる問題が発生した。

その後、TSK-025からTSK-027までのUI改善タスクで、前タスクの実装PR、課題管理PR、CI、merge、作業ブランチ削除、`git fetch origin --prune`、リモートブランチ残存確認を完了してから次タスクへ進む運用を試行した。

この運用により、未merge状態の前タスクを踏み越えて後続タスクを開始する問題を防止できたため、有用性が確認された。

## 対応内容

改善タスク課題一覧へ、順次タスクmergeゲート方針を追加した。

主なルールは以下である。

- 次の正規TSKへ着手する前に、前タスクの実装PRをCI success確認後にmergeする。
- 実装PRとは別に課題管理整理PRが必要な場合、そのPRもCI success確認後にmergeする。
- merge後のリモート作業ブランチを削除する。
- ローカル側で `git fetch origin --prune` を実行する。
- `git branch -r` に当該作業ブランチが残っていないことを確認する。
- これらが完了するまで、次の正規TSKのブランチ作成・実装・PR作成へ進まない。

## 適用例

TSK-025、TSK-026、TSK-027では、以下の流れを適用し、問題の再発がないことを確認した。

1. 最新main確認
2. 作業ブランチ作成
3. 実装PR作成
4. CI success確認
5. squash merge
6. 課題管理PR作成
7. CI success確認
8. squash merge
9. リモート作業ブランチ削除
10. `git fetch origin --prune`
11. `git branch -r` で残存確認
12. 次タスクへ進行

## 完了条件

- 順次タスクmergeゲート方針が明文化されている。 → 完了
- 前タスク完了前に後続TSKへ着手しない基準が明文化されている。 → 完了
- TSK-025〜027で有用性確認済みであることが明記されている。 → 完了
