## 背景

現行の生成結果に含まれる「AI実装指示書」は、利用者が入力した業務要件と生成されたAPI/MCP設計候補をもとに、後続のAIまたは実装者へ実装を依頼するための成果物であるべきである。

しかし修正前の `ImplementationInstructionGenerator` は、冒頭で「APIM for Spring のMVPを段階実装する」と出力し、実装対象として入力フォーム、API/MCP候補生成、結果表示とプレビュー、`BlueprintController` などを扱っていた。

これは、生成対象の業務アプリケーションを実装するための指示書ではなく、APIM for Spring 自体を実装するための内部向け指示書になっていた。

## 目的

AI実装指示書を、APIM for Spring 自体の実装指示ではなく、生成されたREST API候補、DTO候補、Controller雛形、MCP tools/resources/prompts、API/MCP対応表、セキュリティ・承認・監査ログ注意点をもとに、対象業務アプリケーションを後続AIまたは実装者が実装するための指示書へ修正する。

## 再オープン理由

ローカル確認時に、AI実装指示書プレビューへ以下の旧注意文言が再表示されていることを確認した。

```text
APIM for Spring本体の改修指示ではない。
```

この文言は、生成対象アプリ向けの実装指示書であることを説明する目的で追加されていたが、ユーザー確認により削除済みであるべき旧文言として扱った。

現行 `main` では `ImplementationInstructionGenerator` の生成ロジックに当該文言が残存しており、さらに `ImplementationInstructionGeneratorTest` と `BlueprintGenerationRegressionTest` でも当該文言を期待していたため、実装とテストの両方を修正した。

## 実施内容

- `ImplementationInstructionGenerator` から `APIM for Spring本体の改修指示ではない。` を出力しないように修正した。
- `ImplementationInstructionGeneratorTest` の当該文言期待を削除し、再発防止の `doesNotContain` を追加した。
- `BlueprintGenerationRegressionTest` の当該文言期待を削除し、再発防止の `doesNotContain` を追加した。
- 既存の「対象業務アプリケーションを実装するための実装支援AI向け指示」という主旨は維持した。
- APIM内部実装文言を再導入しないことを確認した。
- 新規TSKは作成せず、既存TSK-044の再オープン対応として処理した。

## 実施しないこと

- 新規TSKの作成。
- Render上での実サービス作成。
- Render公開URLの確定。
- 外部LLM API連携。
- DB永続化。
- 認証・認可の本格実装。
- 完全動作するMCPサーバー実装。
- 生成対象アプリの実コード生成。
- 大規模UI全面刷新。

## 完了条件

- AI実装指示書が、APIM for Spring自体ではなく、生成対象業務アプリの実装指示として読める。
- `APIM for Spring本体の改修指示ではない。` がAI実装指示書に出力されない。
- `APIM for Spring のMVPを段階実装する` などの内部実装文言が出力されない。
- 実装指示書に、入力ドメイン、必要操作、AI許可操作、REST API候補、MCP候補、セキュリティ注意点が反映される。
- 後続AIまたは実装者が、生成された設計候補から実装着手するための指示として利用できる。
- 必要最小限のテストが追加・更新され、CIがsuccessである。
