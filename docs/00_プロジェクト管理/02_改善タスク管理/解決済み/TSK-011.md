# TSK-011 生成品質回帰テスト自動化を整備する

- ID: TSK-011
- 件名: 生成品質回帰テスト自動化を整備する
- 状態: 解決済み
- 優先度: High
- 主担当候補: Codex

## 背景

APIM-013では、備品貸出管理、社内申請ワークフロー、ナレッジ検索・要約の3サンプルをブラウザ手入力で確認した。

この方式は確認負荷が高く、今後の命名改善、生成ロジック改善、画面変更時に毎回ユーザーが入力とスクリーンショット貼付を行う運用は非効率である。

## 対応内容

APIM-013で確認した3サンプルを、自動回帰テストとして再利用できる形に整理する。

実装内容:

- 3サンプル入力を `BlueprintInputFixtures` としてテストフィクスチャ化した。
- `BlueprintGenerationRegressionTest` を追加し、サービス層を直接呼び出す生成品質回帰テストを整備した。
- API path、DTO名、MCP tool名、`domain-items` / `DomainItem` フォールバック不在を自動検証する。
- 承認必須、監査ログ、禁止操作の注意点が生成結果に残ることを自動検証する。
- Markdown設計書とAI実装指示書の主要章、初期MVP対象外範囲が維持されることを自動検証する。

## 確認結果

- `powershell -ExecutionPolicy Bypass -NoProfile -File .mvn\wrapper\mvnw-wrapper.ps1 test`: PASS（Tests run: 25, Failures: 0, Errors: 0, Skipped: 0）
- GitHub Actions: PASS（template-checks）

## 完了条件

- 3サンプルの入力がテストコードから再利用できる。
- `domain-items` / `DomainItem` への主要フォールバックを自動検出できる。
- 業務固有語彙がAPI path、DTO名、MCP tool名へ反映されることを自動検証できる。
- 承認必須、監査ログ、Markdown設計書、AI実装指示書の主要要件を自動検証できる。
- Maven Wrapper testとGitHub Actionsで回帰テストが実行される。
## 解決内容

APIM-015としてPR #13で実装され、mainへmerge済み。

主な反映内容:

- BlueprintInputFixtures を追加し、3サンプル入力をテストフィクスチャ化した。
- BlueprintGenerationRegressionTest を追加し、生成品質回帰テストを自動化した。
- BlueprintGenerationServiceTest を更新し、サンプル入力を共通フィクスチャへ寄せた。
- API path、DTO名、MCP tool名、主要フォールバック不在、承認必須、監査ログ、禁止操作注意点、Markdown設計書、AI実装指示書の主要章を自動検証できるようにした。
- Maven Wrapper testおよびGitHub ActionsがPASS済み。
