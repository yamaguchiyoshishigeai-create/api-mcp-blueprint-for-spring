## 背景

Render公開前のローカル確認において、TSK-044で削除済みであるべき旧注意文言 `APIM for Spring本体の改修指示ではない。` がAI実装指示書プレビューに表示されていることが確認された。

このデグレードは、PR #104で生成ロジックと回帰テストを修正し、PR #105で課題管理状態を再同期した。しかし、原因調査の結果、既存の解決済み個票と回帰テストの対応関係を機械的に追跡できない構造上の問題が判明した。

## 判明した問題

- TSK-044初回実装PR #80では、旧文言を禁止語として扱うのではなく、テストが `.contains(...)` で正解扱いしていた。
- 現行mainではMaven testはPASSしているが、解決済みTSKに対する回帰テスト証跡が個票単位で追跡できなかった。
- ChatExec2監査R03では、全56件を処理したうえで `RegressionStrength: NONE`、`Risk: High` と分類された。
- これは、全機能が壊れているという意味ではなく、各個票の完了条件に対して、どのテストがデグレードを検出するかを証明できないという意味である。

## 目的

解決済み個票の完了条件と自動回帰テストを明示的に対応付け、今回のように不適切な文言や仕様がテストで正解扱いされるデグレードを防止する。

## 実施内容

1. `docs/00_プロジェクト管理/06_品質管理/RegressionEvidenceMatrix.md` を追加した。
   - TSK-044の旧注意文言再発防止を初期証跡として登録した。
   - 完了条件、対応テストクラス、対応テストメソッド、正例条件、否定条件、手動確認要否を整理した。
2. `src/test/resources/regression/forbidden-output-phrases.txt` を追加した。
   - 既知禁止語を外部リソースとして管理する形にした。
   - 重要禁止語 `APIM for Spring本体の改修指示ではない` を含めた。
3. `GeneratedOutputForbiddenPhraseGuardTest` を追加した。
   - blueprint markdown と AI implementation instructions に禁止語が含まれないことを横断検査する。
   - `equipmentLoanManagement`、`internalApplicationWorkflow`、`knowledgeSearchAndSummary` の現実的fixtureで検査する。
4. `ForbiddenPhraseLoader` を追加した。
   - `regression/forbidden-output-phrases.txt` を読み込み、空行を除外し、禁止語リストを保持する。
5. `RegressionGuardMetaTest` を追加した。
   - 禁止語リストが空でないことを検査する。
   - 重要禁止語がリストから削除されていないことを検査する。
   - 重要ガードテストクラスが存在することを検査する。
   - `RegressionEvidenceMatrix.md` にTSK-044、既存関連テスト、重要禁止語の証跡が残っていることを検査する。
