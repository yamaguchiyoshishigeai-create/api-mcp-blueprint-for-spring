## 背景

TSK-030で BlueprintInput に systemTypes、primaryDomain、relatedDomains が追加された。

次に、Generatorへ渡す前に旧入力と新入力を一元的に解釈する正規化レイヤを導入し、互換処理が各Generatorへ散在しないようにする。

## 最小実装境界

TSK-031では、Generator前段で利用する NormalizedBlueprintInput と正規化処理を追加する範囲に限定する。

## TSK-031で実施したこと

- NormalizedBlueprintInput を追加した。
- BlueprintInput から NormalizedBlueprintInput を生成する正規化処理を追加した。
- targetDomain のみの旧入力を扱えるようにした。
- primaryDomain と relatedDomains がある場合は新入力を優先するようにした。
- allDomains と targetDomainText を正規化結果として持つようにした。
- BlueprintGenerationService で正規化済み入力を生成し、既存Generator互換用の domainPath / domainClass 生成へ利用した。
- 必要最小限のテストを追加・更新した。

## TSK-031で実施しなかったこと

- Markdown設計書へのドメイン境界表示。
- AI実装指示書へのドメイン境界表示。
- API Generatorの複数ドメイン対応。
- MCP Generatorの複数ドメイン対応。
- ドメイン別Controller、DTO、tool、resource、promptの本格生成。

## 正規化方針

- primaryDomain があれば主ドメインとして優先する。
- primaryDomain が空で targetDomain があれば、targetDomain を分解して先頭を主ドメインとする。
- relatedDomains があれば、主ドメインと重複しない形で関連ドメインにする。
- relatedDomains が空で targetDomain に複数ドメインが含まれる場合、2番目以降を関連ドメインにする。
- targetDomainText は allDomains を区切り文字で連結して作る。
- null、空文字、前後空白、重複は正規化処理で安全に扱う。
