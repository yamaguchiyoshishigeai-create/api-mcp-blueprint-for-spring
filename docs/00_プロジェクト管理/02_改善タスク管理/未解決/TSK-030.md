# TSK-030 複数システム・複数ドメイン入力を内部モデル化する

- ID: TSK-030
- 件名: 複数システム・複数ドメイン入力を内部モデル化する
- 状態: 未解決
- 優先度: High
- 主担当候補: Codex
- 関連文書: `docs/40_詳細設計/複数ドメイン-複合システム入力モデル設計.md`

## 背景

TSK-025〜TSK-027により、UIでは複数システム種別と複数ドメインを選択できるようになった。

しかし、サーバー側の `BlueprintInput` は `targetDomain` を中心とする既存構造を維持しており、選択されたシステム種別、主ドメイン、関連ドメイン群を構造化して保持できていない。

## 実施内容

- `BlueprintInput` に複数システム・複数ドメイン入力を表すフィールドを追加する。
- 候補フィールドとして `systemTypes`、`primaryDomain`、`relatedDomains` を検討する。
- 既存 `targetDomain` は後方互換用として維持する。
- 入力フォーム、バインディング、バリデーション、テストへの影響を確認する。

## 対象外

- `NormalizedBlueprintInput` 導入
- Generatorの複数ドメイン対応
- Markdown設計書のドメイン境界表示
- AI実装指示書のドメイン境界表示

## 完了条件

- 複数システム・複数ドメイン入力を `BlueprintInput` で構造化して扱える。
- 既存の `targetDomain` 入力互換が維持されている。
- テストが更新され、CIがsuccessである。
