# TSK-058 ChatGPTによる通常PR自動merge方針を明文化する

- 件名: ChatGPTによる通常PR自動merge方針を明文化する
- 状態: 未解決

- 主担当候補: ChatGPT(リポジトリ編集)

## 背景

PR #108 の確認時に、ChatGPTが `CI success / mergeable true / scope内 / 未反映事項なし` を確認していたにもかかわらず、mergeをユーザー(人)作業として扱って停止した。

一方、現行運用では、CI完了待ちやmerge後cleanupは自動継続対象として扱われており、通常PRにおけるmerge判断までChatGPT(リポジトリ編集)で実施できるよう整理する必要がある。

現行文書には、ユーザー(人)の担当に `merge判断` が含まれる記述と、PR確認・CI確認・merge判断をChatGPT側で行う前提の記述が併存しており、運用上の矛盾がある。

## 目的

通常PRについて、以下の条件を満たす場合はChatGPT(リポジトリ編集)がmergeまで進められることを明文化する。

- CIが終了条件まで `success` である。
- PRが `mergeable` である。
- 変更内容が事前合意スコープ内である。
- 要求仕様、指定文言、実装方針、テスト期待値、運用規則を弱めていない。
- 未反映事項、CI未確認、PR未作成、main未反映を完了扱いしていない。
- 外部サービス作成、公開判断、費用影響、秘密情報、破壊的変更、主観判断を伴わない。

## 実施すること

1. `docs/00_プロジェクト管理/05_横断運用規程/00_運用ルール索引と実行ゲート.md` を更新する。
2. ユーザー(人)の担当範囲から、通常PRのmerge判断を無条件に含める表現を見直す。
3. 通常PRはChatGPT(リポジトリ編集)がmerge可能であることを明記する。
4. ユーザー(人)へ戻すべきmerge判断の条件を明記する。
5. CI終了条件、merge後cleanup、local syncとの接続を明確化する。
6. `Codex投入前ハンドオフゲート方針.md` 等、既存方針との整合を確認する。

## ユーザー(人)判断へ戻す条件

以下のいずれかに該当する場合は、ChatGPTが自動mergeせず、ユーザー(人)判断へ戻す。

- Public公開、Render等の外部サービス作成、URL公開、費用発生、アカウント設定変更を伴う。
- 秘密情報、権限、認証認可、本番運用、データ削除、破壊的変更を伴う。
- 要求仕様や文言の解釈に主観判断が必要である。
- CI failure、merge conflict、未解決レビュー、未反映事項、scope逸脱がある。
- ユーザーが明示的にmerge前確認を要求している。

## 実施しないこと

- すべてのPRを無条件に自動mergeすること。
- CI未完了またはin_progress状態でmergeすること。
- failure / cancelled / timed_out / action_required をsuccess相当として扱うこと。
- 要求仕様やテスト期待値を弱めてmerge条件を満たしたことにすること。
- merge後cleanup / local syncを省略すること。

## 完了条件

- 通常PRのChatGPT自動merge条件が横断運用規程に明文化されている。
- ユーザー(人)判断へ戻す条件が明文化されている。
- 既存のCI終了条件固定方針、merge後cleanup・local sync方針と矛盾していない。
- 課題一覧にTSK-058が登録されている。
- 実装後、必要に応じて `chatgpt-ops-rules` 側の同等個票と整合している。
