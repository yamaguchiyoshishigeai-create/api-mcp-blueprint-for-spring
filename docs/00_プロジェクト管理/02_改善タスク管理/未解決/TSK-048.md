# TSK-048 CIポーリング終了条件固定方針を明文化する

## 状態

未解決

## 優先度

High

## 主担当候補

ChatGPT(リポジトリ編集)

## 背景

既存の待ちフェーズ運用方針では、GitHub Actions等のCI完了待ち、PR mergeability確定待ち、外部処理完了待ちにおいて、ChatGPTが同一応答ターン内で短時間ポーリングを行うことを定めている。

しかし、`queued` / `in_progress` のまま数回確認しただけで「長引いている」と判断して応答を区切る余地が残っていた。

この問題を防ぐため、`queued` / `in_progress` は終了条件ではないこと、全Jobのsuccess / failure / cancelled / timed_out / 取得不能 / ユーザー割り込み / 異常長時間化のいずれかまで短時間ポーリングを継続することを明文化する。

## 対応内容

1. `CIポーリング終了条件固定方針.md` を横断運用規程として追加する。
2. `queued` / `in_progress` が終了条件ではないことを明文化する。
3. ポーリング継続条件と終了条件を表で整理する。
4. 異常長時間化の例外条件を限定する。
5. CI success後の `CI_GREEN` 扱いと、merge等の後続アクションの分離を明文化する。

## 実施しないこと

- 実装コード変更。
- テストコード変更。
- CI workflow変更。
- merge判断ルールの弱体化。
- `queued` / `in_progress` を終了条件として扱う余地を残すこと。
- 他リポジトリへの横展開。

## 完了条件

- `CIポーリング終了条件固定方針.md` が追加されていること。
- `queued` / `in_progress` が終了条件ではないことが明記されていること。
- success / failure / cancelled / timed_out / 取得不能 / ユーザー割り込み / 異常長時間化の終了条件が明記されていること。
- 異常長時間化の扱いが限定されていること。
- PRのCIがsuccessであること。
- mainへmerge済みであること。

## 後続候補

本対応が有効であることを確認した後、以下のリポジトリへ横展開を検討する。
