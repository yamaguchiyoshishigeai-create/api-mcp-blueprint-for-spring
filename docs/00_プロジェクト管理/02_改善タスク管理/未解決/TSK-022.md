# TSK-022 複数ドメイン・複合システム入力モデルを設計する

- ID: TSK-022
- 件名: 複数ドメイン・複合システム入力モデルを設計する
- 状態: 未解決
- 優先度: High
- 主担当候補: ChatGPT(会話内) / Codex

## 背景

現行の `BlueprintInput` は `targetDomain` を単一文字列として保持している。

しかし実務上の業務システムは、注文管理・商品管理・在庫管理、社員情報管理・経費精算・休暇申請など、複数ドメインを組み合わせて構成されることが多い。

## 課題

単一 `targetDomain` 前提のまま複数ドメインを単純に文字列結合すると、複合システム設計ではなく、長い名前の単一ドメイン設計として扱われるリスクがある。

複数ドメインを扱うには、システム境界、主ドメイン、関連ドメイン、連携方式、外部システム連携を分けて考える必要がある。

## 対応方針

複数ドメイン・複合システム入力モデルを設計する。

設計対象例:

- 対象システム名
- システム種別
- 主ドメイン
- 関連ドメイン群
- 連携方式
- モジュラーモノリス / マイクロサービス / 外部システム連携の扱い
- Generator出力でのドメイン境界表現
- API/MCP設計への反映方針

## 実装方針

本タスクでは、いきなり大規模実装しない。

まず入力モデル・Generator・出力仕様への影響を整理し、必要に応じてCodex実装指示書を作成する。

## 完了条件

- 複数ドメイン入力モデルの設計方針が文書化されている。
- UI、`BlueprintInput`、Generator、Markdown出力、AI実装指示書への影響が整理されている。
- 実装する場合の分割方針とCodex最小指示方針が定義されている。
