# TSK-053 運用ルール改定の横展開要否を判断する

## 状態

未解決

## 優先度

Medium

## 主担当候補

ChatGPT(会話内) / ChatGPT(リポジトリ編集)

## 背景

APIM for Springでは、TSK-047、TSK-048、TSK-050により、以下の運用ルールを追加・明文化した。

1. ローカル一時ファイルとルート直下整理方針。
2. CIポーリング終了条件固定方針。
3. Merge後cleanup・local sync自動統合方針。

これらはいずれもAPIM for Spring固有の問題から発生したが、ChatExec2方式、Codex投入、CI確認、branch cleanup、local syncを利用する他リポジトリにも適用可能な横断運用ルールである。

過去の横展開対象として、`Spring-Tool-Development-Template`、`Q-Scout-for-Spring`、`portfolio` が挙がっている。

ただし、各リポジトリの性質、既存運用規程の有無、ルート直下ファイル構成、CI構成が異なるため、即時横展開ではなく、まず横展開要否と適用範囲を判断する必要がある。

## 対応内容

1. APIM for Springで追加されたTSK-047 / TSK-048 / TSK-050系ルールを棚卸しする。
2. `Spring-Tool-Development-Template` へ横展開すべき内容を確認する。
3. `Q-Scout-for-Spring` へ横展開すべき内容を確認する。
4. `portfolio` へ横展開すべき内容を確認する。
5. 各リポジトリについて、即時反映、部分反映、保留、不要のいずれかを判断する。
6. 必要に応じて後続の横展開実施タスクを分割する。

## 実施しないこと

- 本タスク内での無条件横展開。
- 各リポジトリへの即時PR作成。
- 実装コード変更。
- CI workflow変更。
- APIM for Spring以外のリポジトリ構成を確認せずに文書をコピーすること。

## 完了条件

- 横展開候補リポジトリごとの判断結果が整理されていること。
- 即時反映、部分反映、保留、不要のいずれかが明記されていること。
- 横展開が必要な場合、後続タスクとして分割されていること。
- 判断結果が課題管理または横断運用規程に記録されていること。
- PRのCIがsuccessであること。
- mainへmerge済みであること。
