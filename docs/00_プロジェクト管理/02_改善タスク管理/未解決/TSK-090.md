# TSK-090 POST後画面遷移のPRG化・戻る導線正常化・再送信抑制

- 状態: 未解決

- 登録日: 2026-05-29

## 背景

主要画面のSaaSデザイン統一およびCTA視覚階層整理により、Step1からStep4までの画面体験は改善された。

一方で、POST後画面遷移および戻る導線について、以下の不具合が確認されている。

1. Step3からStep2へブラウザの戻るボタンで戻ると、まだ「フォーム再送信の確認」が表示される。
2. Step3画面下部の「Step2へ戻る」ボタンを押すと、Whitelabel Error Page が表示される。
   - URL: `/external-ai-bridge/prompt`
   - エラー種別: Method Not Allowed
   - HTTPステータス: 405
3. Step4からStep3へブラウザの戻るボタンで戻ると、まだ「フォーム再送信の確認」が表示される。
4. Markdown設計書プレビューからStep4へブラウザの戻るボタンで戻ると、まだ「フォーム再送信の確認」が表示される。

これは見た目やCTA配置の問題ではなく、POSTリクエスト後にHTMLを直接返している画面遷移方式、画面内戻る導線のHTTP method設計、状態復元方式に起因する可能性が高い。

## 目的

POST後画面遷移を見直し、ユーザーがブラウザバック操作または画面内戻るボタンを使用しても、不要なフォーム再送信確認やWhitelabel Error Pageに遭遇しにくい状態にする。

特に、ウィザード型ツールとして以下の体験を目指す。

- Step2、Step3、Step4の前後移動が自然である。
- ブラウザ戻る操作で不要な再送信確認が出にくい。
- Step3下部「Step2へ戻る」などの画面内戻る導線がGET遷移として正常に機能する。
- POST処理結果の再表示が必要な場合も、ユーザーが混乱しない。
- 入力値、検証結果、生成結果の保持範囲が明確である。
- 状態復元できない場合も、Whitelabel Error Pageではなく明確な案内と再入力導線を表示する。

## 対象候補

調査のうえ確定するが、少なくとも以下のPOST後画面と戻る導線を候補とする。

- 自由文入力から外部AI用プロンプト生成へ進む処理
- 外部AI JSON貼り付けまたはアップロード後の検証結果表示処理
- 確認済み内容から設計候補を生成する処理
- Markdown設計書プレビューまたはAI実装指示書プレビューへつながる処理
- Step3下部「Step2へ戻る」ボタン
- Step4からStep3へ戻る導線
- Markdown設計書プレビューからStep4へ戻る導線
- AI実装指示書プレビューからStep4へ戻る導線
- セッション切れ、一時結果消失、GET直アクセス時の復元失敗導線

## 修正方針

### 1. POST/Redirect/GET(PRG)パターンの適用可否を調査する

POSTで処理を実行した後、HTMLを直接返すのではなく、必要に応じて以下の流れへ変更する。

1. POSTで入力・検証・生成処理を実行する。
2. 結果をセッション、Flash Attribute、一時ID、またはサーバー側一時ストアへ保持する。
3. GET画面へredirectする。
4. GET画面で保持済みの結果を表示する。

### 2. 画面内戻る導線をGET遷移として正常化する

Step3下部「Step2へ戻る」ボタンのような戻る導線は、ブラウザ履歴やPOST再送信に依存させず、GETで到達可能な表示画面へ遷移させる。

特に `/external-ai-bridge/prompt` への戻りで Method Not Allowed 405 が出ているため、以下を調査・修正する。

- GET `/external-ai-bridge/prompt` が必要な表示状態を復元できるか
- 戻るボタンがPOST専用URLへGET遷移していないか
- template側の `href` / `form method` / `button type` が意図どおりか
- Controller側にGETハンドラまたは復元失敗時の案内画面があるか
- 復元不能時にWhitelabel Error Pageへ落ちず、再入力導線へ誘導できるか

### 3. 状態保持方式を整理する

画面ごとに保持すべき情報量と寿命が異なるため、以下を整理する。

- Step2: 生成プロンプトMarkdown、元入力、戻る導線
- Step3: JSON検証結果、抽出結果、フォーム反映値、エラー情報
- Step4: 生成結果、Markdown設計書、AI実装指示書、MCP候補、Controller雛形
- プレビュー画面: Step4成果物へ戻るための参照情報
- エラー時: バリデーションエラー、入力値、再試行導線
- セッション切れまたは一時結果消失時: 復元不能メッセージ、再入力導線、トップまたはStep1への導線

### 4. エラー表示と再入力導線を壊さない

PRG化により、エラー表示や入力復元が失われないようにする。

- JSON検証エラー
- 必須入力不足
- 生成不能判定
- アップロード失敗
- 貼り付けJSON不正
- セッション切れまたは一時結果消失
- GET直アクセス時の表示不能
- ブラウザバック後の状態不整合

### 5. ブラウザバック時の期待挙動を明確化する

全画面で完全に任意履歴へ戻せることを目的にしない。

ただし、以下は目標とする。

- 通常操作でブラウザのフォーム再送信確認が出にくい。
- Step2/Step3/Step4のGET表示画面へ戻れる。
- 画面内戻るボタンはGET遷移として正常に動く。
- 状態が失われた場合は、明確な案内と再入力導線を表示する。
- Whitelabel Error Pageへ落ちる導線を削減する。

## 成功条件

- POST後に表示される主要画面が、可能な範囲でGET URLとして再表示できる。
- ブラウザバック操作で「フォーム再送信の確認」が出る場面が削減されている。
- Step3下部「Step2へ戻る」ボタンで Method Not Allowed 405 / Whitelabel Error Page が出ない。
- Step2、Step3、Step4、Markdown設計書プレビュー、AI実装指示書プレビューの既存機能が壊れていない。
- 入力値、JSON検証結果、フォーム反映値、生成結果の表示が維持される。
- エラー時の表示と再試行導線が維持される。
- セッション切れや一時結果消失時のユーザー向け案内がある。
- 画面内戻る導線がPOST専用URLや履歴依存に偏らず、GET遷移として整理されている。
- `git diff --check` が通る。
- `mvnw.cmd test` が通る。
- 必要に応じてControllerTestまたは結合テストが追加・更新されている。

## 実装時の注意

- 見た目変更タスクではなく、Controller遷移設計、Template導線、Session/Flash Attribute/一時保存方式の変更タスクとして扱う。
- Controller/Service/Model/Templateへの影響があるため、TSK-089とは分離して実施する。
- PRG化に伴い、セッションへ過大なデータを長期間保持しない。
- 生成結果や外部AI由来JSONを保持する場合は、保持期間と破棄タイミングを明確にする。
- 戻る操作を完全に保証するより、混乱しない案内と再試行導線を優先する。
- Whitelabel Error Pageをユーザーに見せないため、復元不能時の明示的な画面またはリダイレクトを用意する。
- 既存の外部AI自動送信なし、APIキー保存なしという方針は変更しない。
