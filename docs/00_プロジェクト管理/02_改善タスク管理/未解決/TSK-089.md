# TSK-089 主要画面のボタン・CTA・非操作アイコンの視覚階層統一

- 登録日: 2026-05-28

## 背景

TSK-088により、トップページ基準のSaaSデザイン統一は主要画面へ展開済みである。

一方で、改善後の各ページを通覧した結果、ボタン、CTA、セクションアイコン、表題マークの視覚設計に横断的な不統一が残っていることが判明した。

特に以下の問題が目立つ。

- ボタン文言が上下左右中央に見えない。
- 同一CTAグループ内でボタン高さが揃っていない。
- 文言量に対してボタンが大きすぎる。
- `DL` / `AI` / `MD` などの表題マークや状態マークが、押せるボタンに見える。
- 本来もっとも押してほしい主CTAより、補助導線の方が目立つ箇所がある。
- 「保存」など、実態がダウンロードである箇所の見出し文言が曖昧である。
- モバイル幅やカード内縦積み配置で、ボタンが過剰に大きな塊として見える。

これは個別ページの軽微な見た目調整ではなく、APIM全体のCTA設計ルール、非操作アイコン設計、主従導線の視覚階層が未整理であることに起因する。

## 目的

主要画面に散在するボタン、CTA、非操作アイコン、ダウンロード導線の視覚階層を統一し、ユーザーが「どこを押すべきか」「何は押せない装飾か」を直感的に判断できる状態にする。

## 対象画面

少なくとも以下を対象にする。

- `/external-ai-bridge`
- `/external-ai-bridge/prompt`
- `/external-ai-bridge/import-file`
- Step4結果画面
- `/blueprint/preview`
- `/blueprint/implementation-instructions`
- チェック式入力画面
- 必要に応じて共通CSS

## 現状課題

### 1. ボタン文言の中央配置が不安定

一部ボタンで、文言が上下左右中央に見えず、左寄りまたは上寄りに見える。

### 2. ボタン高さが揃っていない

同一CTAグループ内で、ボタンの高さが微妙に異なる、または縦積み時の高さが過大になる箇所がある。

### 3. ボタンが文言に対して大きすぎる

カード内CTAやモバイル幅の縦積みCTAで、文言量に対してボタンが大きすぎ、画面密度が落ちている。

### 4. 非操作アイコンがボタンに見える

`DL` / `AI` / `MD` などの表題マークが、青ベタ塗り、白文字、角丸、影を持つため、ユーザーに「押せる要素」と誤認される可能性がある。

### 5. 主CTAが補助CTAに埋もれる

ダウンロード画面では、主CTAである `AI実装指示書ダウンロード` や `Markdown設計書ダウンロード` が、補助導線と同格または弱い位置に見える箇所がある。

### 6. 見出し文言が実態とずれる

「保存・再生成」などの見出しが、実態としては「ダウンロード・再生成」または「成果物のダウンロード」に近い箇所がある。

## 修正方針

### 1. CTA階層を定義する

以下のように、CTAの種類ごとに役割と見た目を明確化する。

- Primary CTA:
  - 画面で最も押してほしい操作。
  - 例: ダウンロード、設計候補生成、JSON検証、プロンプト作成。
- Secondary CTA:
  - 補助導線。
  - 例: プレビューへ戻る、設定修正、別画面確認。
- Tertiary CTA:
  - 戻る、トップページへ戻る、補助リンク。
  - 原則としてtext linkまたは弱いoutline扱い。

### 2. ボタンの基本設計を統一する

- ボタン文言は上下左右中央に配置する。
- `display: inline-flex` / `align-items: center` / `justify-content: center` 等で明示する。
- 同一CTAグループ内の高さを揃える。
- デスクトップでは文言に応じた自然な幅を基本にする。
- モバイルではフル幅でもよいが、高さ・余白を抑えて過剰な塊感を避ける。
- 文言折り返しが発生する場合も、中央揃えと高さ整合を維持する。

### 3. 非操作アイコンをボタンと区別する

`DL` / `AI` / `MD` などの非操作マークは、押せる要素と誤認されないよう、以下を検討する。

- ボタンと同じ青ベタ塗りを避ける。
- 淡色背景、線、円形アイコン、小さめのセクションアイコンへ変更する。
- 影を弱める。
- ボタンと同じ高さ・角丸・白文字表現を避ける。
- hover / cursor / focus の表現を持たせない。
- 装飾要素の場合は `aria-hidden="true"` 等を検討する。

### 4. 主CTAを補助CTAより強く見せる

- ダウンロード画面では、ダウンロードボタンを最も目立つ位置と見た目にする。
- `トップページへ戻る` は原則としてtertiary linkまたは弱いボタンにする。
- `設定を修正して再生成` は重要ではあるが、ダウンロードより強く見せない。
- 主CTAと補助CTAを同じ青ベタ塗り・同じサイズ・同じ位置関係にしない。

### 5. 見出し文言を実態に合わせる

必要に応じて、以下のような文言へ整理する。

- `保存・再生成` → `ダウンロード・再生成`
- `保存・再生成` → `成果物のダウンロードと再生成`
- `保存・再生成` → `AI実装指示書のダウンロード`
- `保存・再生成` → `Markdown設計書のダウンロード`

## 成功条件

- 各ページの主要CTAが一目で分かる。
- 非操作アイコンが押せるボタンに見えない。
- ボタン文言が上下左右中央に配置されている。
- 同一CTAグループ内のボタン高さが揃っている。
- 文言に対して過大なボタンが解消されている。
- Primary / Secondary / Tertiary の視覚差が明確である。
- ダウンロード系CTAが補助導線より強く見える。
- モバイル表示でもボタンが過剰に巨大化しない。
- 既存の `href`、`form submit`、`download`、`copy`、`upload`、`JSON検証`、画面遷移が壊れていない。
- `git diff --check` が通る。
- 既存テストが通る。
- 必要に応じて `mvnw.cmd test` が通る。

## 実装時の注意

- まず共通CSS側でボタン/CTA/アイコン設計を標準化する。
- テンプレート修正は、文言・class付与・主CTA配置調整など必要最小限に留める。
- ページ単位の個別上書きCSSを増やしすぎない。
- TSK-088の成果であるSaaSトーンは維持する。
- 見た目改善を理由に既存機能や画面遷移を変更しない。
