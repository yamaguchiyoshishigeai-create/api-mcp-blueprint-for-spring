## 背景

現行の生成結果に含まれる「AI実装指示書」は、利用者が入力した業務要件と生成されたAPI/MCP設計候補をもとに、後続のAIまたは実装者へ実装を依頼するための成果物であるべきである。

しかし現行の `ImplementationInstructionGenerator` は、冒頭で「APIM for Spring のMVPを段階実装する」と出力し、実装対象として入力フォーム、API/MCP候補生成、結果表示とプレビュー、`BlueprintController` などを扱っている。

これは、生成対象の業務アプリケーションを実装するための指示書ではなく、APIM for Spring 自体を実装するための内部向け指示書になっている。

この状態では、初回訪問者が「生成された設計候補をAI実装支援へ渡せる」という価値を期待しても、実際の出力が期待とずれる。

## 目的

AI実装指示書を、APIM for Spring 自体の実装指示ではなく、生成されたREST API候補、DTO候補、Controller雛形、MCP tools/resources/prompts、API/MCP対応表、セキュリティ・承認・監査ログ注意点をもとに、対象業務アプリケーションを後続AIまたは実装者が実装するための指示書へ修正する。

## 実施すること

- `ImplementationInstructionGenerator` の出力目的を、APIM for Spring実装から生成対象アプリ実装へ変更する。
- `APIM for Spring のMVPを段階実装する` 等のAPIM内部実装文言を削除または置換する。
- `BlueprintController` などAPIM内部Controllerを前提にした記述を避ける。
- 入力された対象システム種別、対象ドメイン、必要操作、AI許可操作、出力言語を実装指示書に反映する。
- 生成済みのRESTエンドポイント、DTO候補、Controller雛形、MCP tools/resources/prompts、API/MCP対応表、セキュリティ注意点を、実装対象の材料として整理する。
- 実装すること、実装しないこと、テスト観点、セキュリティ観点、人間確認が必要な操作、監査ログ方針を明確にする。
- 画面上の説明が必要な場合は、「生成された設計候補を実装支援AIへ渡すための指示書」であることが伝わるようにする。
- 既存テストを更新し、不適切なAPIM内部実装文言が出力されないこと、対象ドメイン・操作・API/MCP候補が反映されることを検証する。

## 実施しないこと

- Render公開作業そのもの。
- 複数サンプルボタン化。
- 外部LLM API連携。
- DB永続化。
- 認証・認可の本格実装。
- 完全動作するMCPサーバー実装。
- 生成対象アプリの実コード生成。
- 大規模UI全面刷新。

## 完了条件

- AI実装指示書が、APIM for Spring自体ではなく、生成対象業務アプリの実装指示として読める。
- `APIM for Spring のMVPを段階実装する` などの内部実装文言が出力されない。
- 実装指示書に、入力ドメイン、必要操作、AI許可操作、REST API候補、MCP候補、セキュリティ注意点が反映される。
- 後続AIまたは実装者が、生成された設計候補から実装着手するための指示として利用できる。
- 既存のMarkdown設計書、Controller雛形、結果画面、ダウンロード導線が壊れていない。
- 必要最小限のテストが追加・更新され、CIがsuccessである。
