# TSK-025 対象システム種別プリセットを複数選択UIへ拡張する

- ID: TSK-025
- 件名: 対象システム種別プリセットを複数選択UIへ拡張する
- 状態: 未解決
- 優先度: High
- 主担当候補: ChatGPT(リポジトリ編集) / Codex
- 関連設計書: `docs/40_詳細設計/複数ドメイン-複合システム入力モデル設計.md`

## 背景

現行UIの対象システム種別プリセットは4種類のみであり、実務上の統合システムや複合業務システムを表現するには候補数が不足している。

また、現行UIでは対象システム種別を1つだけ選択する形式であり、複数システム種別を内包する統合システムを自然に表現できない。

## 課題

ユーザーが複合システムを設計したい場合、単一の対象システム種別プリセットでは、複数領域にまたがる業務ドメインを初期選択しにくい。

たとえば、EC販売管理と顧客対応CRMと契約・請求管理を組み合わせたシステムでは、複数のシステム種別を同時に選択し、それぞれに対応するドメイン候補へ自動チェックを入れられる必要がある。

## 対応方針

対象システム種別プリセットを、単一selectから複数選択可能なUIへ変更する。

初期候補は最低10種類とする。

候補例:

- 社内申請ポータル
- EC / 販売管理
- 保守サポート管理
- ナレッジ活用基盤
- 人事労務管理
- 契約・請求管理
- 開発・運用管理
- 顧客対応CRM
- 資産・備品管理
- 統制・監査管理

複数の対象システム種別が選択された場合は、各システム種別に紐づくドメイン候補を合成し、該当するカテゴリ別ドメイン候補へ自動チェックを入れる。

## 実施対象

- 対象システム種別UIの複数選択化
- 対象システム種別候補を最低10種類へ拡充
- システム種別ごとの推奨ドメイン定義の拡充
- 複数システム選択時の推奨ドメイン合成ロジック
- 既存のサンプル入力と送信前集約処理の維持

## 実施しないこと

- `BlueprintInput` の複数ドメインモデル追加
- Generatorの複数ドメイン対応
- Markdown出力のドメイン境界対応
- DB永続化
- 外部LLM連携
- MCPサーバー実装

## 完了条件

- 対象システム種別プリセットが最低10種類になる。
- 対象システム種別を複数選択できる。
- 複数システム種別選択時に、含まれるドメイン候補へ自動チェックが入る。
- 既存のカテゴリ別ドメイン候補、サンプル入力、送信前集約処理が壊れない。
- CIが成功する。
