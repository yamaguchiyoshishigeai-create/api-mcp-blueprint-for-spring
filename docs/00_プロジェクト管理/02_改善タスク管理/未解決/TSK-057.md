## 背景

Render公開前のローカル確認において、TSK-044で削除済みであるべき旧注意文言 `APIM for Spring本体の改修指示ではない。` がAI実装指示書プレビューに表示されていることが確認された。

このデグレードは、PR #104で生成ロジックと回帰テストを修正し、PR #105で課題管理状態を再同期した。しかし、原因調査の結果、既存の解決済み個票と回帰テストの対応関係を機械的に追跡できない構造上の問題が判明した。

## 判明した問題

- TSK-044初回実装PR #80では、旧文言を禁止語として扱うのではなく、テストが `.contains(...)` で正解扱いしていた。
- 現行mainではMaven test 55件はPASSしているが、解決済みTSK 56件に対する回帰テスト証跡が個票単位で追跡できない。
- ChatExec2監査R03では、全56件を処理したうえで `RegressionStrength: NONE`、`Risk: High` と分類された。
- これは、全機能が壊れているという意味ではなく、各個票の完了条件に対して、どのテストがデグレードを検出するかを証明できないという意味である。

## 目的

解決済み個票の完了条件と自動回帰テストを明示的に対応付け、今回のように不適切な文言や仕様がテストで正解扱いされるデグレードを防止する。

## 実施すること

1. `RegressionEvidenceMatrix.md` を追加し、解決済みTSKごとに以下を管理する。
   - TSK ID
   - 完了条件
   - 対応テストクラス
   - 対応テストメソッド
   - 正例条件
   - 否定条件
   - 手動確認が必要な場合の理由
2. 既知の禁止語・禁止仕様を外部ファイルとして管理する。
   - 例: `src/test/resources/regression/forbidden-output-phrases.txt`
3. 生成成果物に対する禁止語ガードテストを追加する。
   - blueprint markdown
   - implementation instructions
   - 必要に応じて画面表示候補
4. 回帰テスト自体の弱体化を検出するメタテストを追加する。
   - 禁止語リストが空でないこと
   - 重要禁止語がリストから消えていないこと
   - 重要テストが存在すること
5. 解決済みTSKに回帰テスト証跡がない場合にCIで検出できる仕組みを検討・導入する。

## 実施しないこと

- TSK-044の再修正。TSK-044はPR #104/#105で修正済み。
- Render上での実サービス作成。
- Render公開URLの確定。
- 外部LLM API連携。
- DB永続化。
- 認証・認可の本格実装。
- 生成対象アプリの実コード生成。

## 完了条件

- 回帰テスト証跡マトリクスが追加されている。
- TSK-044について、旧文言再発を検出できる証跡が明記されている。
- 既知禁止語リストが追加されている。
- 生成成果物に禁止語が含まれないことを検査する自動テストが追加されている。
- 禁止語リストまたは重要ガードテストの削除・空化を検出できるメタテストがある。
- Maven testがsuccessである。
- CIが終了条件までsuccessである。

## 備考

このTSKは、今回のデグレードで判明した横断的な品質管理不備への対応であり、同一問題を新規TSKとして重複起票するものではない。TSK-044本体の文言修正は既に完了しており、本TSKは回帰証跡・テスト防御制度の追加を対象とする。
