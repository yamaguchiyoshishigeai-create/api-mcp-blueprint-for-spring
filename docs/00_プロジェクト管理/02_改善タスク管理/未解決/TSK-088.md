# TSK-088 トップページ基準の主要画面SaaSデザイン統一

状態: 未解決

## 分類

- 登録分類: immediate
- 優先度: High
- MVP整合性: MVP内
- 発生元: post-TSK-071 design consistency review
- 提案名: APIM-UI-CONSISTENCY-001 トップページ基準の全画面SaaSデザイン統一

## 背景

TSK-071により、トップページはWebデザイン担当チャットのレビューも踏まえ、業務ツール系SaaSとして評価の高い書き味・情報設計・視覚表現へ改善された。

一方で、トップページ以外の画面は従来の文体、余白、カード構成、CTA表現、説明順序が残っており、アプリ全体として見ると画面間の品質差が目立つ状態になっている。

## 目的

TSK-071で確立したトップページの書き味、SaaS風デザイン、情報優先順位、CTA表現、カード表現を、主要画面へ展開し、APIM全体のUI/UX品質を揃える。

## 想定変更対象

- チェック式入力画面
- 外部AIプロンプト生成後画面
- JSON取込 / 確認画面
- Markdown設計書プレビュー画面
- AI実装指示書プレビュー画面
- 結果画面
- 必要に応じて共通CSS

## 実装概要

- トップページで採用した濃紺〜青/シアン基調、白カード、薄いボーダー、控えめなシャドウ、整理されたCTA表現を主要画面へ展開する。
- 画面ごとに、利用者が最初に理解すべき目的、入力内容、生成成果物、次アクションを明確化する。
- 既存の業務ロジック、プロンプト生成、JSON取込、プレビュー復帰、ダウンロード導線は変更しない。
- 可能な範囲で共通CSSまたはThymeleaf fragment活用を検討する。
- ただし、共通化そのものが主目的の場合はTSK-077と連携する。

## 既存TSKとの関係

- TSK-071: トップページ単体のターゲット明示・SaaS風UI改善。TSK-088ではそのデザイン基準を他画面へ展開する。
- TSK-073: 結果画面のSaaS風サマリー再構成。TSK-088の中で結果画面全体の書き味統一観点と整合させる。
- TSK-077: Thymeleaf fragment共通化。TSK-088の実装中に共通化が必要になった場合の技術的補助タスクとして扱う。
- TSK-087: スマホ幅・主要画面表示確認。TSK-088完了後の表示確認観点として連携する。

## 完了条件

- 主要画面の見た目・文体・余白・CTA表現がトップページ基準と大きく乖離していない。
- 各画面で、目的、入力内容、生成成果物、次アクションが初見で把握できる。
- 既存のフォーム操作、プロンプト生成、JSON取込、プレビュー、ダウンロード導線が壊れていない。
- 1920x1080、1366x768、タブレット幅、モバイル幅で主要画面の表示崩れがない。
- `git diff --check` と既存テストが通過している。
- 可能であれば主要画面のスクリーンショットまたは表示確認結果がPRに記録されている。

## 実施しないこと

- 認証・認可・ログイン実装
- DB / Migration / Entity / Repository / Service の本格実装
- 保存履歴・再編集機能
- 外部LLM API連携
- 生成ロジックの仕様変更
- 完全動作アプリ生成
- 完全動作MCPサーバー生成
