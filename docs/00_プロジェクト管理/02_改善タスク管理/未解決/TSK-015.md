# TSK-015 APIM入力方式を構造化入力型へ再設計する

- ID: TSK-015
- 件名: APIM入力方式を構造化入力型へ再設計する
- 状態: 未解決
- 優先度: High
- 主担当候補: ChatGPT(会話内) / Codex

## 背景

現行APIMのWeb入力画面は、自然言語の業務要件を入力するとAPI設計とMCP設計の候補を生成するように見える。

一方で、現行実装はLLMを内包しておらず、自由文の意味理解ではなく、固定キーワード検出と固定語彙に基づく静的ルールベース生成である。

そのため、ユーザーがAI的な自由文理解を期待して入力した場合、期待と出力結果の間に落差が生じる可能性が高い。

## 課題

現行UIは、AIへ自由文で要件を投げるWeb入力に近い印象を与える。

しかし現行APIMが安定して扱えるのは、構造化された業務ドメイン、利用者、操作種別、AI許可操作、承認要否、監査ログ要否である。

この不一致を放置したまま機能追加を進めると、APIMの適用領域が誤解され、利用者体験と品質評価が不安定になる。

## 方針

短期方針として、APIMを静的ルールベースMVPに寄せる。

- 入力画面はチェックボックス、選択式、タグ入力などの構造化入力を主導線にする。
- 自由文欄は主要入力ではなく、補足情報または将来LLM抽出レイヤー用の退避様式として扱う。
- 現行のAI風自由文入力様式は削除しない。
- 現行様式は画面表示しない、または開発者向け・将来拡張用テンプレートとして保持する。
- 将来LLMを導入する場合は、自由文から構造化入力を抽出する前段レイヤーとして位置づける。

## 実装対象

- 入力画面の主導線を構造化入力型へ変更する。
- 必要操作、AI許可操作、AI禁止操作、承認必須操作、監査ログ必須操作を選択式にする。
- 対象ドメインはプリセット選択と任意入力を併用できるようにする。
- 既存の `BlueprintInput` 互換性をできるだけ維持し、選択結果を既存の文字列フィールドへ集約して現行Generatorへ渡す。
- 現行自由文入力様式を将来LLM抽出レイヤー用として保持する。

## 完了条件

- ユーザーが、APIMを「自由文意味理解AI」ではなく「選択した構造化要素から設計候補を生成する静的ルールベースMVP」と理解できるUIになっている。
- 既存の生成処理と回帰テストが維持される。
- 現行の自由文入力様式が削除されず、将来LLM抽出レイヤー用に保持されている。
- Codex向け実装指示書が作成されている。
