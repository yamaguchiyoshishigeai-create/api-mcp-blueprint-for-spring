# TSK-070: 軽量エラー履歴ルールをAPIMで先行試行する

状態: 未解決

## 優先度

High

## 主担当候補

ChatGPT(会話内) / ChatGPT(リポジトリ編集) / ChatExec2

## 背景

`chatgpt-ops-rules` の TSK-077 により、軽量エラー履歴ルールをまず実運用中の `api-mcp-blueprint-for-spring` へ先行適用し、運用上の問題点を洗い出してから `Spring-Tool-Development-Template` へ安定版を反映する方針が定義された。

APIMは実運用中であり、ChatExec2、Codex、PR、CI、merge、cleanup、Render公開準備などの作業が継続しているため、軽量エラー履歴の配置先、記録粒度、通常TSK化との境界を検証する先行試行対象として適している。

## 提案名

APIM-ERRORLOG-PILOT-001 APIM軽量エラー履歴先行試行

## 実施内容

- `docs/00_プロジェクト管理/06_運用改善ログ/README.md` を新設する。
- `docs/00_プロジェクト管理/06_運用改善ログ/作業エラー履歴.md` を新設する。
- `docs/README.md` から運用改善ログへ参照導線を追加する。
- 改善タスク台帳へ TSK-070 を登録する。
- APIMでは詳細規程を重複コピーせず、`chatgpt-ops-rules` の現行正本を参照する方針を維持する。

## APIM先行試行で確認する観点

- ログ配置先が実運用上わかりやすいか。
- `作業エラー履歴.md` の粒度が過不足ないか。
- 軽量ログと通常TSKの境界が実際に判断できるか。
- 重大エラーを軽量ログだけで済ませない制約が機能するか。
- ChatExec2失敗時の記録導線が実用的か。
- 中央Inbox Issue方式をすぐ標準化すべきか、補助案に留めるべきか。
- ログファイルが肥大化しすぎないか。
- APIM固有事情を除いた汎用部分をTemplateへ移植できるか。

## 実施しないこと

- TSK-076の詳細規程をAPIMへ丸ごとコピーしない。
- `Spring-Tool-Development-Template` へ未検証のまま反映しない。
- APIM固有の運用ログをTemplateへ持ち込まない。
- 重大エラー、秘密情報混入、GitHub write誤実行、merge / cleanup / local main sync失敗、仕様不変違反を軽量ログだけで済ませる運用にしない。

## 完了条件

- APIM側に軽量エラー履歴の受け口が追加されている。
- APIMで実運用試行する観点が明記されている。
- `docs/README.md` と改善タスク台帳から参照できる。
- 詳細規程を `chatgpt-ops-rules` に置き、APIM側へ重複コピーしていない。
- TSK-070は、APIM先行試行を開始できる状態まで整備された時点で解決済み同期する。
- APIM試行中に発生した問題点は、必要に応じて別TSKまたは `chatgpt-ops-rules` 側の補正候補として扱う。
