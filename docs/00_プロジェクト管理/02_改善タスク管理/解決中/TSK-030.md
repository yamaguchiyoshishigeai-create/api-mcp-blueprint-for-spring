# TSK-030 複数システム・複数ドメイン入力を内部モデル化する

- ID: TSK-030
- 件名: 複数システム・複数ドメイン入力を内部モデル化する
- 状態: 解決中
- 優先度: High
- 主担当候補: 実装支援AI
- 関連文書:
  - `docs/40_詳細設計/複数ドメイン-複合システム入力モデル設計.md`
  - `docs/00_プロジェクト管理/03_実装支援AI指示/TSK-030-最小実装指示.md`

## 背景

TSK-025〜TSK-027により、UIでは複数システム種別と複数ドメインを選択できるようになった。

しかし、サーバー側の `BlueprintInput` は `targetDomain` を中心とする既存構造を維持しており、選択されたシステム種別、主ドメイン、関連ドメイン群を構造化して保持できていない。

## 実施内容

- `BlueprintInput` に複数システム・複数ドメイン入力を表すフィールドを追加する。
- 候補フィールドとして `systemTypes`、`primaryDomain`、`relatedDomains` を検討する。
- 既存 `targetDomain` は後方互換用として維持する。
- 入力フォーム、バインディング、バリデーション、テストへの影響を確認する。

## 最小実装境界

TSK-030では、`BlueprintInput` とフォームバインディングへ複数システム・複数ドメイン入力を保持するための最小フィールドを追加する範囲に限定する。

### TSK-030で実施すること

- `BlueprintInput` に `systemTypes` を追加する。
- `BlueprintInput` に `primaryDomain` を追加する。
- `BlueprintInput` に `relatedDomains` を追加する。
- 既存 `targetDomain` を削除せず、後方互換用として維持する。
- UIから送信される複数システム・複数ドメイン情報を `BlueprintInput` にbindできるようにする。
- 既存 `targetDomain` ベースのGenerator出力を壊さない。
- 必要最小限のテストを追加・更新する。

### TSK-030で実施しないこと

- `NormalizedBlueprintInput` 導入。
- Generatorの複数ドメイン対応。
- Markdown設計書のドメイン境界表示。
- AI実装指示書のドメイン境界表示。
- API Generatorの本格的な複数ドメイン対応。
- MCP Generatorの本格的な複数ドメイン対応。
- ドメイン別Controller、DTO、tool/resource/promptの生成。

## 対象外

- `NormalizedBlueprintInput` 導入
- Generatorの複数ドメイン対応
- Markdown設計書のドメイン境界表示
- AI実装指示書のドメイン境界表示

## 完了条件

- 複数システム・複数ドメイン入力を `BlueprintInput` で構造化して扱える。
- 既存の `targetDomain` 入力互換が維持されている。
- フォーム送信で新フィールドが `BlueprintInput` にbindされる。
- TSK-031〜034の範囲へ越境していない。
- テストが更新され、CIがsuccessである。
