# 課題管理ID体系

## 1. 目的

APIM for Spring プロジェクトにおける課題・作業・成果物の識別子を整理し、今後の運用上の混乱を防止する。

これまで、作業単位を表す `APIM-###` と、改善タスクを表す `TSK-###` が併用されていた。しかし、会話、PR、成果物、課題管理で参照する番号が二重化し、同一作業の追跡性が低下していた。

本方針では、今後の正規IDを `APIM-###` に統一する。

## 2. 正規ID

今後の正規課題IDは `APIM-###` とする。

対象:

- 企画
- 要件定義
- 基本設計
- 実装指示
- 実装
- レビュー
- 改善
- テスト整備
- 運用整備
- ドキュメント整備

## 3. TSK IDの扱い

`TSK-###` は既存履歴としてのみ保持する。

新規の `TSK-###` 採番は停止する。

既存のTSK個票や改善タスク課題一覧は、過去の参照互換性を保つため、当面リネームしない。

既存TSKとAPIM作業の対応関係は、同ディレクトリの `旧TSK対応表.md` で管理する。

## 4. 新規課題の採番規則

新規課題は、次の未使用 `APIM-###` を採番する。

例:

- `APIM-016 課題管理ID体系統一`
- `APIM-017 次期改善テーマ`

新規課題では、原則として `TSK-###` を併記しない。

ただし、既存TSKに関連する後続作業の場合は、本文中の参考情報として旧TSK IDを記載してよい。

## 5. ファイル命名規則

新規の課題個票または作業指示書は、原則として `APIM-###` をファイル名に含める。

例:

- `APIM-016-課題管理ID体系統一.md`
- `APIM-017-XXXX-Codex実装指示書-v0.1.md`

既存の `TSK-###.md` は履歴として維持する。

## 6. 運用段階

本方針はPhase 1として適用する。

Phase 1:

- 新規TSK採番停止
- APIM IDを正規IDとして明文化
- 旧TSK対応表を追加
- 既存TSKファイルは維持
- ディレクトリ名は変更しない

Phase 2以降で検討する事項:

- APIM課題一覧の新設
- 新規APIM個票ディレクトリの整備
- `02_改善タスク管理` ディレクトリ名の見直し
- READMEや導線の再整理

## 7. 注意事項

既存のPR、AI_REPO_RESULT、会話履歴、文書内参照が `TSK-###` を参照しているため、既存TSKの一括リネームは行わない。

ID体系統一は、今後の運用をAPIM IDへ寄せる段階的移行として扱う。
