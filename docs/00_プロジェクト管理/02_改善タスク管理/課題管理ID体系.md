# 課題管理ID体系

## 1. 目的

APIM for Spring プロジェクトにおける作業タスク、改善課題、実装指示、レビュー指摘、運用改善、ドキュメント整備の識別子を統一し、二重採番を防止する。

本方針では、正規タスクIDを `TSK-###` に統一する。

## 2. 正規タスクID

本リポジトリにおける正規タスクIDは `TSK-###` とする。

対象:

- 作業タスク
- 改善課題
- 実装指示
- レビュー指摘
- 運用改善
- ドキュメント整備
- テスト整備

## 3. 独自タスクIDの新設禁止

プロジェクト名、製品名、機能名、フェーズ名、略称をもとに、独自のタスクIDを新設してはならない。

禁止例:

- `APIM-###`
- `PROJ-###`
- `FEAT-###`
- `MVP-###`
- その他、`TSK-###` 以外のタスク採番

`APIM` はプロジェクト名または説明上の名称としてのみ使用する。

## 4. APIMという名称の扱い

`APIM for Spring` はプロジェクト名である。

過去の会話や文書では、`APIM-###` が作業テーマ名のように使われた経緯があるが、今後は課題管理IDとして使用しない。

作業名にAPIMという語を含める場合も、正規タスクIDは `TSK-###` とする。

例:

- 正: `TSK-012 タスク採番方針をTSK正規IDへ是正する`
- 正: `TSK-013 APIM for Spring のREADME導線を改善する`
- 誤: `APIM-012 タスク採番方針を是正する`
- 誤: `APIM-013 README導線を改善する`

## 5. 記録対象

以下では正規参照IDとして `TSK-###` を使用する。

- 改善タスク課題一覧
- 個票ファイル名
- PRタイトル
- PR本文
- AI_REPO_RESULT
- Codex指示書
- ChatGPT作業指示
- コミットメッセージ
- ドキュメント内の課題参照

## 6. 運用ルール

新規タスクを追加する場合は、既存の最大 `TSK-###` を確認し、最大番号+1を採番する。

採番済み番号の再利用は禁止する。

作業テーマ名やプロジェクト名に別の略称を含めても、正規タスクIDは `TSK-###` とする。

## 7. 今回の是正理由

前回のID体系整理では、`APIM-###` を正規課題IDとする方針を採用した。

しかし、Spring-Tool-Development-Template では作業タスク採番として `TSK-###` を使う前提であり、派生リポジトリでもこれに従うべきであった。

今回の二重採番の直接原因は、テンプレートで `TSK-###` が定義されていたにもかかわらず、ChatGPTがプロジェクト名 `APIM` から `APIM-###` という独自タスク採番を作り、課題IDのように運用したことである。

そのため、今後は `TSK-###` を唯一の正規タスクIDとし、`APIM-###` の新規タスク採番は禁止する。

## 8. Spring-Tool-Development-Templateへの反映方針

今後作成する新規リポジトリでも同じ混乱を防ぐため、Spring-Tool-Development-Template には以下を反映する。

- 正規タスクIDは `TSK-###` のみとする
- プロジェクト名由来の独自タスクIDを禁止する
- ChatGPT / Codex / ユーザーの作業指示でも `TSK-###` を正規参照IDとして使う
- PR、台帳、個票、AI_REPO_RESULT、Codex指示書のIDを `TSK-###` に統一する
