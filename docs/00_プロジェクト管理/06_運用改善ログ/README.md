# 運用改善ログ

このディレクトリは、APIM for Spring における軽量エラー履歴の受け口である。

## 正本参照

軽量エラー履歴・ライフサイクル管理方式の詳細な正本は、`yamaguchiyoshishigeai-create/chatgpt-ops-rules` の現行規程を参照する。

APIM側では、詳細規程を重複コピーせず、APIM固有の軽微な作業エラー、ChatExec2実行上の違和感、Codex指示不備、ChatGPT応答運用ミスなどを記録する受け口だけを保持する。

## 対象

- ChatExec2実行時の軽微な再実行ミス。
- OS差分やパス差分による軽微な失敗。
- Codex投入指示やChatGPT応答の軽微な不足。
- 再発監視したいが、直ちに通常TSK化するほどではない作業エラー。
- APIM先行試行中に見つかったログ配置・記録粒度・導線上の問題。

## 軽量ログだけで済ませてはならない事象

以下は、軽量エラー履歴だけで済ませず、通常TSK化または即時個票化を検討する。

- 秘密情報、token、`.env`、秘密鍵、個人情報の混入。
- GitHub write誤実行。
- merge / cleanup / local main sync の失敗。
- 仕様不変原則違反。
- データ損失リスク。
- 外部公開、費用、権限、承認に関わる問題。
- ユーザー判断が必要な未解決課題。

## APIM先行試行の確認観点

- ログ配置先が実運用上わかりやすいか。
- `作業エラー履歴.md` の粒度が過不足ないか。
- 軽量ログと通常TSKの境界が実際に判断できるか。
- 重大エラーを軽量ログだけで済ませない制約が機能するか。
- ChatExec2失敗時の記録導線が実用的か。
- 中央Inbox Issue方式を標準化すべきか、補助案に留めるべきか。
- ログファイルが肥大化しすぎないか。
- APIM固有事情を除いた汎用部分をTemplateへ移植できるか。
