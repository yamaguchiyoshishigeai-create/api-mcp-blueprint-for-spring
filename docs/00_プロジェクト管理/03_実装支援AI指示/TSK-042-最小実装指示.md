# TSK-042 最小実装指示

## 1. 作業名

TSK-042 初回訪問者向け体験ルートを実装する

## 2. 目的

APIM for Springを初めて訪問した利用者が、サンプル入力から生成まで迷わず進み、API設計書、MCP tools/resources/prompts、API/MCP対応表、AI実装指示書の価値を短時間で理解できる体験ルートを実装する。

Render公開前に、公開URLへ来た訪問者が「何を入力すればよいか」「何が出力されるか」「生成結果を次にどう使えるか」を理解できる状態にする。

## 3. 推奨Codex設定

| 項目 | 推奨値 | 理由 |
|---|---|---|
| モデル | 利用可能な最新・高精度のコード生成向けモデル | Thymeleaf画面、Controller、入力モデル、テストを横断して変更する可能性があるため。 |
| インテリジェンス | 高 | 初回体験導線、既存自由入力互換、MVP対象外の明示を同時に扱うため。 |
| 速度 | 標準〜低速寄り | 体験導線の分かりやすさと既存生成フローの破壊防止を優先するため。 |

## 6. 実施すること

- 入力画面またはトップ画面に、APIM for Springでできることを短く説明する。
- 初回訪問者が迷わず試せるサンプル入力導線を追加する。
- サンプル導線は、少なくとも以下のような価値が伝わるものにする。
  - 主ドメインと関連ドメインが分かる。
  - API設計とMCP設計が同時に生成される。
  - AI実装指示書へつながることが分かる。
- サンプル例は、既存の生成品質テストやドメイン語彙と整合するものを優先する。
- 推奨サンプルは「注文管理 / 在庫管理 / 商品管理」など、複数ドメインの価値が伝わる業務例とする。
- サンプル投入後も、既存の自由入力フローを壊さない。
- 生成後画面またはプレビュー領域に、出力物の見方を短く説明する。
- 生成物がCodex等の実装支援AIへの入力に使えることを明示する。
- まだ生成しないものを誤解なく明示する。
- 必要最小限のテストを追加・更新する。

## 7. 実施しないこと

- Render公開作業そのもの。
- 外部LLM API連携。
- DB永続化。
- 認証・認可の本格実装。
- 完全動作するMCPサーバー実装。
- ユーザー入力履歴の保存。
- アクセス解析やイベントトラッキングの本格実装。
- 大規模なUI全面刷新。

## 8. 実装上の注意

- 既存の自由入力フォームを壊さないこと。
- サンプル入力は、既存の `BlueprintInput` に自然にbindできる形にすること。
- 複数システム種別、主ドメイン、関連ドメイン、必要操作、AI許可操作、承認要否が分かるサンプルにすること。
- 初回訪問者向け説明は長すぎず、画面上で読める短い導線にすること。
- 出力説明では、生成されるものと生成されないものを明確に分けること。
- 既存テストで検証している生成内容を不必要に変更しないこと。
- CSSやテンプレート変更は最小限に留め、保守しやすい構成にすること。

## 9. テスト観点

少なくとも以下を確認する。

- 初期表示で、APIM for Springの用途説明が表示されること。
- サンプル導線が画面に表示されること。
- サンプル入力を利用して生成処理へ進めること。
- 生成後に、API設計書、MCP設計候補、AI実装指示書の見方が説明されること。
- 既存の自由入力からの生成が壊れていないこと。
- 完全MCPサーバーやDB実装を生成するものではないことが明示されること。

実行コマンド:

```bash
# Windows
./mvnw.cmd test

# Linux/macOS/WSL
./mvnw test
```
