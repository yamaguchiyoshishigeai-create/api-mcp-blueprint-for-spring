# TSK-034 最小実装指示

## 1. 作業名

TSK-034 MCP Generatorを複数ドメイン対応へ拡張する

## 2. 目的

TSK-031で導入された `NormalizedBlueprintInput` と正規化レイヤ、TSK-032で追加された生成成果物上のドメイン境界表示、TSK-033で追加されたAPI Generatorの主ドメインAPI・関連ドメイン参照API境界を前提に、MCP設計生成を主ドメイン・関連ドメイン・横断操作の境界を意識した候補生成へ拡張する。

本タスクはMCP Generatorのtools / resources / prompts候補とAPI/MCP対応表を複数ドメイン対応へ拡張する最小実装であり、完全動作するMCPサーバー実装やMCP仕様ファイルの完全生成には踏み込まない。

## 3. 推奨Codex設定

| 項目 | 推奨値 | 理由 |
|---|---|---|
| モデル | 利用可能な最新・高精度のコード生成向けモデル | Java既存構造、MCP Generator、API/MCP対応表、正規化済み入力、回帰テストを同時に扱うため。 |
| インテリジェンス | 高 | 完全MCPサーバー実装へ越境せず、設計候補生成の最小拡張に留める判断が必要なため。 |
| 速度 | 標準〜低速寄り | 速度よりも既存単一ドメイン互換、安全側のAI実行可否分類、テスト整合性を優先するため。 |

## 6. 実施すること

- MCP tools候補を主ドメイン操作と関連ドメイン参照操作に分ける。
- MCP resources候補を主ドメインresourceと関連ドメインresourceに分ける。
- MCP prompts候補に、複数ドメイン横断時の利用場面、禁止事項、人間確認条件を反映する。
- API/MCP対応表を、TSK-033で拡張された主ドメインAPI・関連ドメイン参照APIの境界に合わせる。
- AI実行可否、承認要否、監査ログ要否がドメイン境界と矛盾しないようにする。
- `NormalizedBlueprintInput` または正規化済み情報を利用できる場合は利用する。
- 旧入力 `targetDomain` のみの入力でも、既存どおりMCP設計候補を生成できる状態を維持する。
- 単一ドメイン入力では、既存の生成結果互換をできるだけ維持する。
- 必要最小限のテストを追加・更新する。

## 7. 実施しないこと

- 完全動作するMCPサーバー実装。
- MCP仕様への完全準拠検証。
- tool実行ランタイム実装。
- LLM接続処理の実装。
- 認証・認可コードの自動実装。
- DB Entity / Repository / Service完全実装。
- OpenAPI / MCP仕様ファイルの完全生成。

## 8. 実装上の注意

- 本タスクは「MCP設計候補のドメイン境界対応」が目的であり、MCPサーバーの実行可能実装ではない。
- 既存Generatorの責務を大きく変えない。
- 既存テストの期待値が変わる場合は、差分理由をTSK-034のMCP Generator表示・候補整理に限定する。
- 主ドメインtoolsは中心となる業務操作として扱う。
- 関連ドメインtoolsは原則として参照・要約・連携補助に限定し、書き込み系や削除系を過剰生成しない。
- resourcesは原則読み取り専用として扱い、更新はtools経由の設計候補とする。
- promptsには、禁止事項、人間確認条件、センシティブ情報の扱いを含める。
- null、空文字、空リストのケースでMarkdown出力が壊れないようにする。

## 9. テスト

少なくとも以下を確認する。

- 単一ドメイン入力で既存MCP設計候補が壊れないこと。
- 旧入力 `targetDomain` のみでもMCP設計候補が破綻しないこと。
- `primaryDomain` と `relatedDomains` を指定した場合、主ドメインtoolsと関連ドメイン参照toolsの境界が確認できること。
- resources候補がドメイン境界を意識して生成されること。
- prompts候補に横断利用場面、禁止事項、人間確認条件が反映されること。
- API/MCP対応表がTSK-033のAPI境界と整合すること。
- 完全MCPサーバー実装へ越境していないこと。

実行コマンド:

```bash
# Windows
./mvnw.cmd test

# Linux/macOS/WSL
./mvnw test
```
