# TSK-033 最小実装指示

## 1. 作業名

TSK-033 API Generatorを複数ドメイン対応へ拡張する

## 2. 目的

TSK-031で導入された `NormalizedBlueprintInput` と正規化レイヤ、TSK-032で追加された生成成果物上のドメイン境界表示を前提に、API設計生成を主ドメイン・関連ドメインの境界を意識した候補生成へ拡張する。

本タスクはAPI Generatorの出力候補を複数ドメイン対応へ拡張する最小実装であり、MCP Generatorのtool/resource/prompt分割や実Controller実装生成には踏み込まない。

## 3. 推奨Codex設定

| 項目 | 推奨値 | 理由 |
|---|---|---|
| モデル | 利用可能な最新・高精度のコード生成向けモデル | Java既存構造、API Generator、正規化済み入力、回帰テストを同時に扱うため。 |
| インテリジェンス | 高 | TSK-034へ越境せず、API Generatorの最小拡張に留める判断が必要なため。 |
| 速度 | 標準〜低速寄り | 速度よりも既存単一ドメイン互換、出力安定性、テスト整合性を優先するため。 |


## 6. 実施すること

- API Generatorで主ドメインAPIと関連ドメイン参照APIを分ける。
- Controller候補が過大にならないよう、ドメイン別Controller候補を生成する。
- DTO候補をドメイン別に生成する。
- `NormalizedBlueprintInput` または正規化済み情報を利用できる場合は利用する。
- 旧入力 `targetDomain` のみの入力でも、既存どおりAPI設計候補を生成できる状態を維持する。
- 単一ドメイン入力では、既存の生成結果互換をできるだけ維持する。
- 必要最小限のテストを追加・更新する。

## 7. 実施しないこと

- MCP Generatorの複数ドメイン対応。
- tool / resource / prompt 候補のドメイン別分割。
- 実際のController実装生成。
- DB Entity / Repository / Service完全実装。
- 永続化設計の本格拡張。
- TSK-034の範囲に含まれる実装。

## 8. 実装上の注意

- 本タスクは「API設計候補のドメイン境界対応」が目的であり、実コード生成の完全分割ではない。
- 既存Generatorの責務を大きく変えない。
- 既存テストの期待値が変わる場合は、差分理由をTSK-033のAPI Generator表示・候補整理に限定する。
- 主ドメインは中心となる業務APIとして扱う。
- 関連ドメインは参照・連携先として扱い、主ドメインと同等の過剰なAPI候補を生成しない。
- null、空文字、空リストのケースでMarkdown出力が壊れないようにする。
- TSK-034で扱うMCP Generatorのtool/resource/prompt候補へは踏み込まない。

## 9. テスト

少なくとも以下を確認する。

- 単一ドメイン入力で既存API設計候補が壊れないこと。
- 旧入力 `targetDomain` のみでもAPI設計候補が破綻しないこと。
- `primaryDomain` と `relatedDomains` を指定した場合、主ドメインAPIと関連ドメイン参照APIの境界が確認できること。
- Controller候補がドメイン境界を意識して生成されること。
- DTO候補がドメイン境界を意識して生成されること。
- TSK-034の範囲へ越境していないこと。

実行コマンド:

```bash
# Windows
./mvnw.cmd test

# Linux/macOS/WSL
./mvnw test
```
