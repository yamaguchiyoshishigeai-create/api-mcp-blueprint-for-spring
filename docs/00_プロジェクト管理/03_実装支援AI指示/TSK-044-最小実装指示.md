# TSK-044 最小実装指示

## 1. 作業名

TSK-044 AI実装指示書を生成対象アプリ向けに修正する

## 2. 目的

APIM for Springの生成結果に含まれる「AI実装指示書」を、APIM for Spring自体の実装指示ではなく、利用者が入力した業務要件と生成されたAPI/MCP設計候補をもとに、後続AIまたは実装者が対象業務アプリケーションを実装するための指示書へ修正する。

現行の `ImplementationInstructionGenerator` は、冒頭で「APIM for Spring のMVPを段階実装する」と出力し、入力フォーム、API/MCP候補生成、結果表示、`BlueprintController` などAPIM内部実装を前提にしている。

TSK-044では、この設計不整合を修正し、生成されたREST API候補、DTO候補、Controller雛形、MCP tools/resources/prompts、API/MCP対応表、セキュリティ・承認・監査ログ注意点を材料に、対象業務アプリケーションを実装するためのAI実装指示書を生成する。

## 3. 推奨Codex設定

| 項目 | 推奨値 | 理由 |
|---|---|---|
| モデル | 利用可能な最新・高精度のコード生成向けモデル | 生成器とテストを横断して修正するため。 |
| インテリジェンス | 高 | 出力成果物の意味をAPIM内部実装から生成対象アプリ実装へ切り替える設計修正のため。 |
| 速度 | 標準〜低速寄り | 文言品質、生成設計の整合性、回帰テストを優先するため。 |

## 6. 現状課題

現行のAI実装指示書は、生成対象アプリではなくAPIM for Spring自体を実装する指示に見える。

特に以下が問題である。

- 「APIM for Spring のMVPを段階実装する」と出力される。
- 実装対象として入力フォーム、API/MCP候補生成、結果表示とプレビューが示される。
- `BlueprintController` などAPIM内部のController名を前提にしている。
- 利用者が入力した対象ドメイン、必要操作、AI許可操作、生成されたREST API候補、MCP候補が、後続AI向けの実装作業単位として十分に整理されていない。

## 7. 実施すること

### 7.1 ImplementationInstructionGeneratorの出力目的を修正する

`ImplementationInstructionGenerator` の出力目的を、APIM for Spring実装から生成対象業務アプリ実装へ変更する。

出力冒頭は、以下の趣旨になるよう修正する。

- この指示書は、生成されたAPI/MCP設計候補をもとに、対象業務アプリケーションを実装するための実装支援AI向け指示である。
- 入力された業務要件、対象ドメイン、必要操作、AI許可操作、セキュリティ注意点を実装材料として扱う。
- APIM for Spring本体の実装指示ではない。

### 7.2 APIM内部実装文言を除去する

以下のような文言や同趣旨の出力を出さないようにする。

- `APIM for Spring のMVPを段階実装する`
- `入力フォーム`
- `API/MCP候補生成`
- `結果表示とプレビュー`
- APIM内部の `BlueprintController` を実装対象として扱う記述

ただし、生成されたController雛形の一般的なController名や対象業務アプリのController候補は出力してよい。

### 7.3 生成済み設計候補を実装材料として整理する

AI実装指示書には、最低限以下を含める。

- 対象システム種別。
- 対象ドメイン。
- 必要操作。
- AI許可操作。
- 出力言語。
- RESTエンドポイント候補。
- DTO候補。
- Controller雛形またはController実装候補。
- MCP tools/resources/prompts候補。
- API/MCP対応表。
- セキュリティ・承認・監査ログ注意点。

### 7.4 後続AIが使いやすい構造へ整理する

指示書には以下の章立てを含める。

- 実装目的。
- 実装対象システム。
- 入力業務要件の要約。
- 実装するREST API。
- 実装するDTO / 入出力モデル。
- 実装するController / Service候補。
- 実装するMCP tools/resources/prompts。
- API/MCP対応方針。
- 認証・認可・承認・人間確認・監査ログ方針。
- 実装しないこと。
- テスト観点。
- 後続AIへの注意事項。

章名は実装に合わせて調整してよいが、上記の意味は維持する。

### 7.5 result画面の説明を必要に応じて修正する

`result.html` にAI実装指示書の説明文がある場合は、以下の趣旨へ修正する。

- APIM for Springを実装するための指示書ではない。
- 生成された設計候補を、Codex等の実装支援AIへ渡すための指示書である。
- 利用者の対象業務アプリケーション実装へつなげるための成果物である。

### 7.6 テストを追加・更新する

必要最小限のテストを追加・更新する。

少なくとも以下を検証する。

- AI実装指示書に `APIM for Spring のMVPを段階実装する` が含まれないこと。
- AI実装指示書がAPIM内部の入力フォームや結果表示機能を実装対象として扱わないこと。
- 入力された対象ドメイン、必要操作、AI許可操作がAI実装指示書へ反映されること。
- RESTエンドポイント候補がAI実装指示書へ反映されること。
- MCP tools/resources/prompts候補がAI実装指示書へ反映されること。
- セキュリティ・承認・監査ログ注意点がAI実装指示書へ反映されること。
- 既存の生成結果画面表示やMarkdownダウンロード導線が壊れていないこと。

## 8. 実施しないこと

- Render公開作業そのもの。
- 複数サンプルボタン化。
- 外部LLM API連携。
- DB永続化。
- 認証・認可の本格実装。
- 完全動作するMCPサーバー実装。
- 生成対象アプリの実コード生成。
- 大規模UI全面刷新。
- TSK-045候補で扱う複数サンプル業務パターン追加。
