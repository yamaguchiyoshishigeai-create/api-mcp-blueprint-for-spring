# TSK-032 最小実装指示

## 1. 作業名

TSK-032 Markdown設計書とAI実装指示書にドメイン境界を表示する

## 2. 目的

TSK-031で導入された `NormalizedBlueprintInput` と正規化レイヤを前提に、生成されるMarkdown設計書およびAI実装指示書で、対象システム種別、主ドメイン、関連ドメイン、正規化後ドメイン一覧を確認できるようにする。

本タスクは、複数ドメイン入力の責務境界を成果物上に表示するための最小実装であり、API GeneratorやMCP Generatorの本格的な複数ドメイン分解には踏み込まない。

## 3. 推奨Codex設定

| 項目 | 推奨値 | 理由 |
|---|---|---|
| モデル | 利用可能な最新・高精度のコード生成向けモデル | Java既存構造、Generator境界、Markdown出力、回帰テストを同時に扱うため。 |
| インテリジェンス | 高 | TSK-033/034へ越境せず、表示層への最小反映に留める判断が必要なため。 |
| 速度 | 標準〜低速寄り | 速度よりも既存生成結果の後方互換、テスト整合、出力文言の安定性を優先するため。 |

## 6. 実施すること

- Markdown設計書に、対象システム種別、主ドメイン、関連ドメイン、正規化後ドメイン一覧を表示する入力サマリーを追加する。
- AI実装指示書に、主ドメインと関連ドメインの実装境界に関する注意を追加する。
- TSK-031で導入された `NormalizedBlueprintInput` または正規化済み情報を利用できる場合は利用する。
- 旧入力 `targetDomain` のみの入力でも、既存どおり成果物を生成できる状態を維持する。
- 単一ドメイン入力でも過剰な複数ドメイン表現にならないようにする。
- 複数システム種別が選択された場合、Markdown設計書とAI実装指示書のどこかで確認できるようにする。
- 必要最小限のテストを追加・更新する。

## 7. 実施しないこと

- API Generatorの複数ドメイン対応。
- MCP Generatorの複数ドメイン対応。
- Controller候補のドメイン別分割。
- DTO候補のドメイン別分割。
- tool / resource / prompt 候補のドメイン別分割。
- ドメインごとの完全な生成成果物分解。
- TSK-033またはTSK-034の範囲に含まれる実装。

## 8. 実装上の注意

- 本タスクは「出力上の境界表示」が目的であり、「生成候補の完全なドメイン別分解」ではない。
- 既存Generatorの責務を大きく変えない。
- 既存テストの期待値が変わる場合は、差分理由をTSK-032の表示追加に限定する。
- 表示文言は、後続実装者が主ドメインと関連ドメインの違いを判断できる粒度にする。
- `NormalizedBlueprintInput` がすでに生成サービス内で利用されている場合、その情報を二重正規化しない。
- null、空文字、空リストのケースでMarkdown出力が壊れないようにする。

## 9. テスト

少なくとも以下を確認する。

- 単一ドメイン入力で既存生成が壊れないこと。
- 旧入力 `targetDomain` のみでもドメイン境界サマリーが破綻しないこと。
- `primaryDomain` と `relatedDomains` を指定した場合、Markdown設計書に主ドメイン・関連ドメインが表示されること。
- AI実装指示書に実装境界の注意が表示されること。
- `systemTypes` を指定した場合、対象システム種別が表示されること。

実行コマンド:

```bash
# Windows
./mvnw.cmd test

# Linux/macOS/WSL
./mvnw test
```
