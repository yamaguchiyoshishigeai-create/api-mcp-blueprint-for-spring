# TSK-031 最小実装指示

## 1. 目的

TSK-031では、`BlueprintInput` からGenerator前段で利用する `NormalizedBlueprintInput` を生成する正規化レイヤを導入する。

本タスクは、旧入力互換と新入力優先の解釈をGeneratorの外側へ集約するための足場整備である。Markdown出力、AI実装指示書、API Generator、MCP Generatorの本格的な複数ドメイン対応までは行わない。

## 2. 対象リポジトリ

- `yamaguchiyoshishigeai-create/api-mcp-blueprint-for-spring`

## 3. 実装対象ファイル候補

主な対象候補は以下である。

- `src/main/java/com/example/apim/model/NormalizedBlueprintInput.java`
- `src/main/java/com/example/apim/service/BlueprintInputNormalizer.java`
- `src/main/java/com/example/apim/service/BlueprintGenerationService.java`
- `src/test/java/com/example/apim/service/BlueprintInputNormalizerTest.java`
- `src/test/java/com/example/apim/service/BlueprintGenerationServiceTest.java`
- 必要に応じた回帰テスト

上記以外のファイルを変更する場合は、TSK-031の最小実装境界内である理由をPR本文に明記する。

## 4. 追加する最小モデル

`NormalizedBlueprintInput` は、以下のrecordを候補とする。

```java
public record NormalizedBlueprintInput(
    List<String> systemTypes,
    String primaryDomain,
    List<String> relatedDomains,
    List<String> allDomains,
    String targetDomainText,
    BlueprintInput originalInput
) {
}
```

## 5. フィールド責務

| フィールド | 目的 |
|---|---|
| `systemTypes` | 入力された複数システム種別 |
| `primaryDomain` | Generator上の主ドメイン |
| `relatedDomains` | 主ドメイン以外の関連ドメイン群 |
| `allDomains` | 主ドメイン + 関連ドメインの重複排除済み一覧 |
| `targetDomainText` | 既存Generator互換用のドメイン文字列 |
| `originalInput` | 既存Generator、Markdown、AI指示書との互換維持用の元入力 |

## 6. 正規化ルール

以下のルールを実装する。

1. `primaryDomain` があれば、それを主ドメインとする。
2. `primaryDomain` が空で `targetDomain` があれば、`targetDomain` を分解して先頭を主ドメインとする。
3. `relatedDomains` があれば、主ドメインと重複しない形で関連ドメインにする。
4. `relatedDomains` が空で `targetDomain` に複数ドメインが含まれる場合、2番目以降を関連ドメインにする。
5. `targetDomainText` は `allDomains` を ` / ` で連結して作る。
6. 何もない場合は既存Validationに委ね、正規化処理側で過剰な例外を出さない。

## 7. targetDomain分解ルール

TSK-030以前からUIでは複数ドメインを ` / ` 区切りで扱っている。

例:

```text
注文管理 / 商品管理 / 在庫管理
```

期待する正規化結果:

| 正規化項目 | 値 |
|---|---|
| `primaryDomain` | `注文管理` |
| `relatedDomains` | `商品管理`, `在庫管理` |
| `allDomains` | `注文管理`, `商品管理`, `在庫管理` |
| `targetDomainText` | `注文管理 / 商品管理 / 在庫管理` |

## 8. null・空値・重複処理

| 入力 | 方針 |
|---|---|
| null | 空として扱う |
| 空文字 | 除外 |
| 前後空白 | trimする |
| 同一ドメイン重複 | 先勝ちで1件にする |
| `primaryDomain` と `relatedDomains` の重複 | `primaryDomain` を優先し、関連から除外する |
| `systemTypes` の重複 | 先勝ちで1件にする |

## 9. BlueprintGenerationService接続方針

`BlueprintGenerationService` で正規化済み入力を作成し、既存Generatorの入力には互換用文字列を使う。

最小変更例:

```java
NormalizedBlueprintInput normalized = normalizer.normalize(input);

String domainPath = domainNameNormalizer.normalizeUrlSegment(normalized.targetDomainText());
String domainClass = domainNameNormalizer.normalizeClassName(normalized.targetDomainText());
```

ただし、既存Generatorへ `NormalizedBlueprintInput` を直接渡すような大改修は行わない。

- AI実装指示書へのドメイン境界表示。

- MCP Generatorの複数ドメイン対応。
- ドメイン別Controller候補生成。
- ドメイン別DTO候補生成。
- tool/resource/promptのドメイン境界別生成。
- 既存Generatorの引数構造の大規模変更。
