# TSK-030 最小実装指示

## 1. 目的

TSK-030では、APIM for Springの入力モデル `BlueprintInput` に、複数システム種別・複数ドメイン入力を保持するための最小フィールドを追加する。

本タスクは、後続のTSK-031〜TSK-034へ進むための入力モデル足場整備である。Generatorの本格的な複数ドメイン対応や正規化レイヤ導入までは行わない。

## 2. 対象リポジトリ

- `yamaguchiyoshishigeai-create/api-mcp-blueprint-for-spring`

## 3. 実装対象ファイル候補

主な対象候補は以下である。

- `src/main/java/com/example/apim/model/BlueprintInput.java`
- `src/main/resources/templates/index.html`
- `src/test/java/com/example/apim/controller/BlueprintControllerTest.java`
- `src/test/java/com/example/apim/testsupport/BlueprintInputFixtures.java`
- 必要に応じた `BlueprintInput` 関連テスト

上記以外のファイルを変更する場合は、TSK-030の最小実装境界内である理由をPR本文に明記する。

## 4. 追加する最小フィールド

`BlueprintInput` に、以下のフィールドを追加する。

```java
private List<String> systemTypes = new ArrayList<>();
private String primaryDomain = "";
private List<String> relatedDomains = new ArrayList<>();
```

型・初期値は既存JavaBean構造との整合を優先し、null安全に扱う。

| フィールド | 型 | 初期値 | 目的 |
|---|---|---|---|
| `systemTypes` | `List<String>` | 空リスト | 複数選択された対象システム種別を保持する |
| `primaryDomain` | `String` | 空文字 | 主ドメインを保持する |
| `relatedDomains` | `List<String>` | 空リスト | 関連ドメイン群を保持する |
| `targetDomain` | `String` | 既存維持 | 後方互換・表示・手動補正用に維持する |

## 5. 後方互換方針

既存 `targetDomain` は削除しない。

現時点のGenerator群は `targetDomain` を前提に動作しているため、TSK-030では既存 `targetDomain` ベースの出力を破壊しないことを最優先する。

`primaryDomain` / `relatedDomains` から `targetDomain` を派生する正規化処理は、TSK-031の `NormalizedBlueprintInput` 導入時に扱う。

## 6. フォームバインディング方針

UIから送信される複数システム・複数ドメイン情報を `BlueprintInput` にbindできるようにする。

実装時は以下を確認する。

- 対象システム種別の複数選択値が `systemTypes` にbindされる。
- 主ドメイン相当の値が `primaryDomain` にbindされる。
- 関連ドメイン群が `relatedDomains` にbindされる。
- 既存 `targetDomain` は従来どおり送信・bindされる。
- 対象ドメイン欄の手動補正を妨げない。

既存UIの再設計や大幅な見た目変更は行わない。

## 7. バリデーション方針

既存 `BlueprintInput` の方針に合わせ、過大入力を防止する。

推奨は以下である。

- `primaryDomain` には `@Size(max = 100)` 相当を付ける。
- `systemTypes` / `relatedDomains` は要素数や各要素長の過剰化を避ける。
- Jakarta Validationで自然に表現できる範囲に留める。
- 実装が複雑化する場合、TSK-030では最小限に留め、詳細な正規化・検証は後続へ送る。

## 8. TSK-030で実施しないこと

以下は実施しない。

- `NormalizedBlueprintInput` の作成。
- `BlueprintInput` からGenerator向け正規化モデルへの変換。
- API Generatorの複数ドメイン対応。
- MCP Generatorの複数ドメイン対応。
- Markdown設計書へのドメイン境界表示。
- AI実装指示書へのドメイン境界表示。
- ドメイン別Controller候補生成。
- ドメイン別DTO候補生成。
- tool/resource/promptのドメイン境界別生成。

## 9. テスト方針

最低限、以下を確認する。

| テスト対象 | 確認内容 |
|---|---|
| `BlueprintInput` | `systemTypes` / `primaryDomain` / `relatedDomains` がnull安全に保持される |
| 後方互換 | `targetDomain` だけの既存入力が引き続き有効である |
| Controller | 複数値フォーム送信が `BlueprintInput` にbindされる |
| 既存サービス | `BlueprintGenerationService` 等の既存 `targetDomain` 利用が破壊されない |
| 全体 | Maven testがsuccessになる |

## 10. 実行すべきコマンド

Windows環境では以下を実行する。

```powershell
./mvnw.cmd test
```

Linux/macOS/WSL環境では以下を実行する。

```bash
./mvnw test
```

CIではLinux / Windowsの両方がsuccessであることを確認する。
