# TSK-046 最小実装指示

## 1. 作業名

TSK-046 初回訪問者向けサンプル業務パターンを複数化する

## 2. 目的

APIM for Springの初回訪問者向けサンプル導線を、単一の注文管理サンプルから3〜4種類の業務パターンへ拡張する。

初見ユーザーが自分の業務に近い入口を選び、APIM for Springが注文管理専用ではなく、複数の業務要件からREST API、MCP設計候補、API/MCP対応表、AI実装指示書を生成できる汎用設計支援ツールであることを理解できる状態にする。

## 3. 対象ブランチ候補

```text
feature/tsk-046-multi-sample-entry-route
```

## 5. サンプル候補

以下4種類を基本候補とする。

1. 注文・在庫管理サンプル。
   - EC、販売管理、在庫引当、出荷管理などの基本例。
2. 社内申請・承認ワークフローサンプル。
   - 承認、人間確認、監査ログ、差戻しなどの価値を示す例。
3. 問い合わせ・サポート管理サンプル。
   - FAQ検索、問い合わせ分類、AI要約、返信下書きなどの価値を示す例。
4. 契約・請求管理サンプル。
   - 権限、承認、外部通知、請求状態、監査ログ、実務リスク管理を示す例。

既存の注文管理サンプルは、注文・在庫管理サンプルとして維持または自然に拡張する。

## 6. 実施すること

- サンプル投入ボタンを1種類から3〜4種類へ増やす。
- 各サンプルに、何の業務を想定したものかを短く説明する。
- 各サンプルを選ぶと、対象システム種別、ドメイン、必要操作、AI許可操作、自由入力などが自然に設定されるようにする。
- 初見ユーザーが「自分の業務に近い入口」を選べるUI文言にする。
- 複数サンプルが、生成結果のREST API候補、MCP候補、AI実装指示書に違いとして現れるようにする。
- 既存の自由入力フローと注文管理サンプル導線を壊さない。
- 必要最小限のControllerテストまたは画面テストを追加・更新する。

## 7. 実施しないこと

- TSK-045のプレビューダウンロード導線追加。
- TSK-045の入力状態復元導線追加。
- Render公開作業そのもの。
- 外部LLM API連携。
- DB永続化。
- 認証・認可の本格実装。
- 完全動作するMCPサーバー実装。
- 大規模UI全面刷新。

## 8. テスト観点

- 初回訪問者向けサンプル業務パターンが3〜4種類表示されること。
- 各サンプルの意味と想定業務が画面上で分かること。
- サンプル選択により、対象業務に応じた入力設定が反映されること。
- 選択したサンプル業務ごとに、生成結果へ違いが反映されること。
- 既存の注文管理サンプル導線と自由入力POSTフローが壊れていないこと。
