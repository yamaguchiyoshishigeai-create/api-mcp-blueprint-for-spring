# 回帰証跡記録ルール

## 1. 目的

本書は、APIM for SpringでTSKを解決済みにする際、当該課題対応に対するデグレードを検出できる証跡を過不足なく記録するためのリポジトリ固有ルールである。

横断ルールの正本は `chatgpt-ops-rules` の `回帰テスト必要十分性ゲート` とする。本書はAPIM側の適用ルールである。

## 2. 必須記録項目

TSKを解決済みにする場合、個票、PR本文、完了報告、または `RegressionEvidenceMatrix.md` に以下のいずれかを記録する。

```text
回帰証跡:
- 新規/更新テスト:
- 既存テストで十分な根拠:
- メタテスト/静的検査:
- 手動確認証跡:
- 対象外根拠:
- 後続TSK:
```

## 3. 自動回帰テスト必須の目安

以下に該当する変更は、原則として自動回帰テストまたは既存自動テストでの検出根拠を必要とする。

- Blueprint生成ロジック。
- Markdown設計書生成ロジック。
- AI実装指示書生成ロジック。
- API Generator / MCP Generator。
- UI導線、フォーム入力、プリセット、ダウンロード。
- 複数ドメイン・複数システム入力モデル。
- 禁止語、旧仕様、APIM本体制約混入の再発防止。

## 4. 静的検査または手動確認で十分な目安

以下に該当する変更は、自動Javaテストではなく、静的検査、ドキュメント確認、PR/CI/ChatExec2結果、手動確認証跡で十分な場合がある。

- ドキュメント整理。
- 課題一覧・個票同期。
- アーカイブ移動。
- `.gitignore` やルート直下ノイズ整理。
- 運用規程・手順文書。
- Render公開前チェックや公開後確認の記録。
- ローカル環境依存の確認。

ただし、対象外または手動確認で十分と判断した理由を記録する。

## 5. DONE判定

回帰証跡の要否判断が未記録のまま、TSKを解決済みにしてはならない。

自動テストが必要な変更で、テスト未追加、既存テスト充足根拠なし、CI未確認、または代替証跡なしの場合は、未完了または後続TSKありとして扱う。

## 6. TSK-001〜TSK-056棚卸しとの関係

既存TSK-001〜TSK-056の初回棚卸し結果は `RegressionEvidenceInventory_TSK001_TSK056.md` に記録する。

今後、各TSKに対して不足が見つかった場合は、該当TSKの棚卸し行を根拠に、個別の後続TSKとして対応する。
