# TSK-057 回帰テスト証跡と禁止語ガード調査報告

## 1. 調査目的

Render公開前のローカル確認において、TSK-044で削除済みであるべき旧注意文言 `APIM for Spring本体の改修指示ではない。` がAI実装指示書プレビューへ表示された。

本報告は、以下を目的とする。

1. デグレード発生経緯と直接原因を明確化する。
2. 同種デグレードを防ぐ対策案を整理する。
3. 解決済み個票に対する回帰テスト十分性を再評価する。
4. 回帰テスト自体が弱体化・破壊されるリスクへの防御策を定義する。

## 2. 発生事象

AI実装指示書プレビューに、以下の旧注意文言が表示された。

    APIM for Spring本体の改修指示ではない。

この文言は、生成対象アプリ向けの実装指示書であることを説明する目的で過去に追加されたが、Render公開前のユーザー確認により、削除済みであるべき旧文言として扱うことが確定した。

## 3. Git履歴上の経緯

### 3.1 TSK-044初回実装

TSK-044の目的は、AI実装指示書をAPIM for Spring本体の改修指示ではなく、利用者が入力した業務要件から作る対象業務アプリケーション向けの実装指示へ修正することだった。

しかし、初回実装PR #80では、生成ロジックに `APIM for Spring本体の改修指示ではない。` が出力される状態となった。

さらに、`ImplementationInstructionGeneratorTest` でも同文言を `.contains(...)` として期待しており、当該文言が出力されることを正解として固定していた。

### 3.2 デグレード検出不能化

この時点で、テストは「旧文言を検出するガード」ではなく、「旧文言を期待する正例」になっていた。

そのため、後続のMaven testやCIでは、当該文言の残存をデグレードとして検出できなかった。

### 3.3 修正対応

PR #104で以下を実施した。

- `ImplementationInstructionGenerator` から旧文言を削除。
- `ImplementationInstructionGeneratorTest` で旧文言を `.doesNotContain(...)` として検査。
- `BlueprintGenerationRegressionTest` でも旧文言を `.doesNotContain(...)` として検査。

PR #105で、ローカル確認R02成功を踏まえ、TSK-044を再度解決済みに同期した。

## 4. 直接原因

直接原因は、TSK-044初回対応時に、生成対象アプリ向けであることを説明する文言と、ユーザーに見せるべきでない内部説明文言の境界を誤ったことである。

加えて、当該文言をテストで禁止条件として扱わず、正例として扱ったため、回帰テストがデグレードを検出できなかった。

## 5. 構造原因

### 5.1 個票完了条件とテストの対応不備

解決済み個票の完了条件が、どの自動テストで守られているかを示す証跡が不足している。

そのため、個票が解決済みになっていても、対応する仕様・禁止条件・UI出力・生成物出力が回帰テストで守られているかを機械的に確認できない。

### 5.2 否定条件の不足

既存テストには、期待される正例出力を `.contains(...)` で検査するものが多い一方、出てはいけない文言、戻してはいけない仕様、弱めてはいけない方針を検査する否定条件が不足している。

### 5.3 回帰テスト自体の弱体化検出不足

禁止語や禁止仕様がテスト本文に散在している場合、テスト本文の修正により、禁止語チェック自体が削除・弱体化されても検出されにくい。

今回も、当初は旧文言が `.contains(...)` で期待されていたため、テストそのものが仕様と逆方向に働いていた。

## 8. 再発防止案

### 8.1 Regression Evidence Matrix の導入

`docs/00_プロジェクト管理/06_品質管理/RegressionEvidenceMatrix.md` を追加し、各TSKについて以下を管理する。

| 項目 | 内容 |
|---|---|
| TSK ID | 対象個票ID |
| 完了条件 | 個票上の完了条件 |
| 対応テストクラス | 自動テストクラス名 |
| 対応テストメソッド | 自動テストメソッド名 |
| 正例条件 | 出るべき文言・成立すべき挙動 |
| 否定条件 | 出てはいけない文言・壊れてはいけない挙動 |
| 手動確認 | 手動確認が必要な場合の理由と手順 |

### 8.2 禁止語リストの外出し

`src/test/resources/regression/forbidden-output-phrases.txt` を追加し、生成物に出てはいけない文言をテスト本文から外部化する。

初期候補は以下とする。

    APIM for Spring本体の改修指示ではない
    APIM for Spring のMVPを段階実装する
    - APIM for Spring本体の改修
    完全動作するMCPサーバーは実装しない
    - 入力フォーム
    - API/MCP候補生成
    - 結果表示とプレビュー
    TSK-032ではController、DTO、tool、resource、promptのドメイン別分割は行わない

### 8.3 生成物横断ガードテスト

生成される以下の成果物に対して、禁止語が含まれないことを検査する。

- blueprint markdown
- implementation instructions
- 必要に応じて画面表示候補

### 8.4 回帰テストメタガード

以下を検査するメタテストを追加する。

- 禁止語リストが空でないこと。
- 重要禁止語が禁止語リストから削除されていないこと。
- 重要ガードテストクラスが存在すること。
- `RegressionEvidenceMatrix.md` にTSK-044など重要タスクの証跡があること。

### 8.5 CIでの証跡チェック

将来的には、解決済みTSKについて `RegressionEvidenceMatrix.md` に証跡がない場合、CIで検出する。

ただし、既存56件すべてに対して一度に厳格適用すると作業量が大きいため、段階導入とする。

## 9. 推奨実施順序

1. TSK-057として、TSK-044を対象に最小の禁止語リスト・生成物横断ガードテスト・メタガードを導入する。
2. `RegressionEvidenceMatrix.md` を追加し、まずTSK-044の証跡を登録する。
3. 以後、新規TSKまたは再オープンTSKについて、完了時に証跡追加を必須化する。
4. 既存TSK-001〜TSK-056は、High Risk棚卸しとして段階的に証跡を追加する。
5. 十分に証跡が揃った段階で、CIの証跡チェックをwarningからfailureへ引き上げる。

## 10. 結論

今回のデグレードは、単一の文言修正漏れではなく、個票完了条件と回帰テストの対応証跡が不足していること、さらに否定条件とテスト自体の防御が不足していることから発生した。

TSK-044本体は修正済みだが、同種の再発を防ぐには、回帰テスト証跡マトリクス、禁止語リスト、生成物横断ガードテスト、メタガードテストを導入する必要がある。
