# Regression Evidence Matrix

## 1. 文書目的

本書は、解決済み改善タスクの完了条件と回帰テスト証跡を対応付けるためのマトリクスである。

目的は以下である。

1. 解決済みTSKの完了条件が、どの自動テストまたは手動確認で守られているかを明示する。
2. 生成物に出てはいけない文言・仕様が、正例として固定されるデグレードを防止する。
3. 回帰テスト自体の削除・空化・弱体化を検出できる状態を作る。
4. CodexやChatGPTが後続作業を行う際、どの仕様を弱めてはならないかを参照できるようにする。

## 2. 運用方針

- 新規TSKまたは再オープンTSKを解決済みに移す際は、原則として本マトリクスへ回帰証跡を追加する。
- すべてのTSKに即時で完全な自動テストを要求するのではなく、重要度の高い仕様から段階的に登録する。
- 自動テストで守れるものは対応テストクラスと対応テストメソッドを記録する。
- 手動確認が必要なものは、手動確認理由と確認手順を記録する。
- 禁止語・禁止仕様は、可能な限り `src/test/resources/regression/forbidden-output-phrases.txt` などの外部ファイルに集約する。
- 安全チェックやツール制約を回避する目的で、完了条件、禁止語、否定条件、テスト期待値を弱めてはならない。

## 5. 段階導入メモ

現時点では、TSK-044を最初の重要証跡として登録する。

既存TSK-001〜TSK-056すべてへ一括で厳格証跡を要求すると作業量が大きいため、TSK-057では以下に限定する。

1. TSK-044旧注意文言再発防止の証跡を登録する。
2. 禁止語リストを外部化する。
3. 生成物横断ガードテストを追加する。
4. メタガードテストで禁止語リストと重要証跡の削除・空化を検出する。

TSK-057完了後、既存TSK-001〜TSK-056全件の証跡拡充が必要と判断される場合は、別TSKとして段階整備を検討する。
