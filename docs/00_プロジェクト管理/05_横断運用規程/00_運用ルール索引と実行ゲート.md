# 運用ルール索引と実行ゲート

## 1. 目的

本書は、APIM for Spring の作業開始時に、共通運用ルール正本とAPIM固有ルールの参照関係を確認するための入口文書である。

共通運用ルールの正本は `yamaguchiyoshishigeai-create/chatgpt-ops-rules` とする。

本書は、共通運用ルール本文をAPIM側へ重複コピーしない。詳細な共通規程は `chatgpt-ops-rules` 側を参照する。

## 3. APIM固有前提

APIM for Spring では、以下をAPIM固有前提として維持する。

1. APIMは診断系ではなく設計生成系である。
2. 初期MVPは設計生成に限定する。
3. 完全動作するMCPサーバーや本格Spring Bootアプリケーション生成は現時点の対象外である。
4. 生成対象は、API設計書、MCP設計書、API/MCP対応表、Spring Controller雛形、AI実装指示書である。
5. Render公開操作、外部サービス操作、費用発生、公開判断はユーザー(人)の判断対象である。

## 4. 作業開始ゲート

APIM for Spring の作業開始時は、以下を確認する。

1. Memory上のプロジェクト運用ルール。
2. `chatgpt-ops-rules` の `PROJECT_START_PROMPT.md`。
3. `chatgpt-ops-rules` の横断運用規程入口。
4. APIM側の `PROJECT_START_PROMPT.md`。
5. APIM側の `README.md`。
6. APIM側の `docs/README.md`。
7. APIM側の改善タスク課題一覧。
8. Open PRの有無。
9. 直前タスクのmerge、remote branch削除、local main同期、prune確認の完了状態。
10. APIM固有の要件定義、設計、実装、公開準備文書。

## 5. 衝突時の優先順位

共通運用ルールとAPIM側文書に矛盾がある場合、共通運用ルールは `chatgpt-ops-rules` を優先する。

ただし、APIM固有の業務仕様、実装仕様、環境依存手順、Render公開準備、製品前提はAPIM側文書を優先する。

## 7. 共通ルール本文の重複禁止

以下はAPIM側へ本文を重複コピーしない。

- ChatExec / ChatExec2方式の一般規程。
- 通常PR自動merge方針。
- 個票先行main反映ゲート。
- FullFlow bat一括実行方針。
- Codex投入前ハンドオフゲート。
- 安全チェック発生時の仕様不変切替方針。
- 発生・残存課題の個票化最優先ルール。
- 実行計画と実行指示の分離方針。

必要な場合は、`chatgpt-ops-rules` の該当規程を参照する。

## 8. DONE判定

APIM側の作業は、以下が完了するまでDONE扱いしない。

1. 対象PRがmainへmerge済みである。
2. 必要な課題管理整理が完了している。
3. remote作業ブランチが削除済みである。
4. local mainがorigin/mainへ同期済みである。
5. `git fetch origin --prune` が完了している。
6. remote tracking branchが残っていない。
7. 発生・残存課題の未個票化がないことを確認している。
