# Codexプロンプト運用方針

## 1. 目的

本方針は、Codex等の実装支援AIへ渡すプロンプトに、実装指示だけでなく、推奨実行設定、コミット、push、Pull Request作成、Issue/PRコメントによる実行状況引き継ぎを必ず含めるための横断運用規程である。

これにより、実装支援AIによる作業がローカル差分で停止したり、PR化されないまま残ったり、後続のChatGPTが実行状況を把握できなくなる問題を防止する。

## 2. 適用範囲

本方針は、以下の作業に適用する。

- Codexへ実装作業を依頼する場合。
- Gemini、GitHub Copilot、その他の実装支援AIへ同等の実装作業を依頼する場合。
- 実装、テスト、commit、push、PR作成までを一連の作業として依頼する場合。
- ChatGPTが実装支援AI向けプロンプトを作成する場合。

## 3. CodexExec指示書・結果ファイル名方針

Codex向け実行指示書をファイルとして配布する場合、固定ファイル名 `CodexExec.md` に限定しない。

また、Codexの詳細補足結果ファイルも固定ファイル名 `CodexExec.result` に限定しない。

原則として、指示書と結果ファイルは同じ作業識別子を持つ一意なファイル名を使用する。

標準形式:

- `CodexExec_<作業内容>.md`
- `CodexExec_<作業内容>.result`

例:

- `CodexExec_TSK043_visitor_value_route.md`
- `CodexExec_TSK043_visitor_value_route.result`
- `CodexExec_TSK041_render_prepare.md`
- `CodexExec_TSK041_render_prepare.result`
- `CodexExec_docs_wait_phase_policy.md`
- `CodexExec_docs_wait_phase_policy.result`

この方針の目的は、複数のCodex作業指示書・結果ファイルを同じダウンロードフォルダまたは作業ディレクトリで扱う場合に、ファイル名衝突、上書き、旧指示書の誤投入、旧結果との混同、作業内容の取り違えを防止することである。

作業内容部分には、TSK ID、対象機能、対象工程など、利用者と後続AIが識別しやすい短い英数字・ハイフン・アンダースコアを用いる。

機密情報、個人情報、環境固有の不要な絶対パス、トークン等をファイル名に含めてはならない。

短い単一工程の指示はチャット本文に提示してよい。長大な指示、複数工程の指示、commit・push・PR作成・PRコメント投稿まで含む指示、または後続確認や再実行の可能性がある指示は、原則として `CodexExec_<作業内容>.md` として配布可能な形式にする。

## 4. Codex実行結果の主記録と補足結果ファイル

Codexの実行結果は、原則としてGitHub IssueまたはPull Requestコメントへサニタイズ済み要約として記載する。

Issue/PRコメントへ記載する主内容は、以下を標準とする。

- JOB_ID。
- STATUS。
- 対象リポジトリ。
- 対象ブランチ。
- commit SHA。
- PR番号。
- 実行した主要コマンド。
- 変更ファイル一覧。
- テスト結果サマリ。
- CI結果サマリ。
- 次に必要な判断事項。
- 実行開始時刻。
- 実行終了時刻。

`CodexExec_<作業内容>.result` は、Issue/PRコメントだけでは不足する場合の詳細補足結果ファイルとして扱う。

`CodexExec_<作業内容>.result` に出力する内容の例:

- 長めの補足説明。
- 追加検証結果。
- ローカル実行時の詳細要約。
- 失敗時の原因切り分けメモ。
- Issue/PRコメントへ載せるには長いが、ChatGPT確認には必要なサニタイズ済みログ抜粋。

`CodexExec_<作業内容>.result` は必須出力ではない。Issue/PRコメントで十分に引き継げる場合は、作成しなくてもよい。

詳細補足が必要な場合、ユーザーは `CodexExec_<作業内容>.result` をChatGPTへ添付または貼り付け、ChatGPTが内容を確認して次工程を判断する。

## 5. Codexプロンプトに必ず含める項目

Codex等の実装支援AI向けプロンプトには、以下を必ず含める。

1. 対象リポジトリ。
2. 対象ブランチ。
3. 作業名またはTSK ID。
4. 参照すべき正本ドキュメント。
5. 実装すること。
6. 実装しないこと。
7. 後続タスクへ残すこと。
8. 実行すべきテストコマンド。
9. commit手順。
10. push手順。
11. Pull Request作成手順。
12. Pull Request本文に記載すべき項目。
13. Issue/PRコメントへ投稿する実行状況引き継ぎ情報。
14. 機密情報を投稿しないための注意。

## 6. 推奨設定の併記

Codex向けプロンプトを提示する場合は、プロンプト本文と併せて以下の推奨設定を明記する。

| 項目 | 必須性 | 内容 |
|---|---:|---|
| 推奨モデル | 必須 | 利用可能な最新または高精度のコード生成向けモデルを指定する。 |
| 推奨インテリジェンス | 必須 | 低・標準・高など、必要な推論品質を指定する。 |
| 推奨速度 | 必須 | 高速・標準・低速寄りなど、速度と品質の優先度を指定する。 |
| 推奨理由 | 必須 | その設定を選ぶ理由を簡潔に記載する。 |

実装、複数ファイル変更、テスト追加、既存互換、TSK越境防止を伴う場合は、原則としてインテリジェンスは高、速度は標準から低速寄りを推奨する。

## 7. commitからPR作成までの指示必須化

実装支援AI向けプロンプトでは、実装後に以下を実施するよう明記する。

1. 変更ファイルを確認する。
2. 必要なテストを実行する。
3. テスト結果を確認する。
4. `git add -A` 等で変更をステージングする。
5. 作業内容が分かるcommit messageでcommitする。
6. 対象作業ブランチをremoteへpushする。
7. `main`等の指定base branchへPull Requestを作成する。
8. Pull Request本文へ、実施内容、未実施内容、テスト結果、後続作業を記載する。

Codex等がGitHub CLIを利用できない環境では、PR作成に必要なタイトル、本文、head branch、base branchを出力させる。

## 8. Issue/PRコメントによる実行状況引き継ぎ

Codex向けプロンプトの最後段には、ChatExec2方式に倣い、IssueまたはPull Requestコメントへ投稿する実行状況サマリのテンプレートを必ず含める。

コメントには以下を含める。

- JOB_ID。
- STATUS。
- 対象リポジトリ。
- 対象ブランチ。
- commit SHA。
- 実行した主なコマンド。
- 変更ファイル一覧。
- テスト結果サマリ。
- CI結果サマリ。
- 次に必要な判断事項。
- 実行開始時刻。
- 実行終了時刻。

## 9. コメント・補足結果ファイル記載時の禁止事項

Issue/PRコメントおよび `CodexExec_<作業内容>.result` には、以下を含めてはならない。

- APIキー。
- アクセストークン。
- `.env` の内容。
- 秘密鍵。
- フル環境変数。
- 個人情報。
- 不要な絶対パス。
- 長大なログ全文。
- 機密性の高いエラー詳細。
- 認証情報、接続文字列、Cookie、セッション情報。

詳細ログが必要な場合でも、サニタイズ済み要約を優先する。

## 10. 実行状況コメントの標準テンプレート

Codexプロンプトには、以下の形式を標準テンプレートとして含める。

```text
JOB_ID: <一意な作業ID>
STATUS: SUCCESS | FAIL
Repository: <owner/repo>
Branch: <作業ブランチ>
Commit: <commit SHA>
Commands:
- <実行した主要コマンド>
Changed Files:
- <変更ファイル>
Test Summary: <テスト結果の要約>
CI Summary: <CI結果または確認待ち>
Next Actions: <レビュー待ち、CI待ち、merge判断待ち等>
Start: <開始時刻>
End: <終了時刻>
```

## 11. ChatGPTがプロンプト作成時に確認すること

ChatGPTがCodex向けプロンプトを作成する場合は、提示前に以下を確認する。

- 推奨モデル、インテリジェンス、速度が記載されていること。
- 実装範囲と対象外範囲が分離されていること。
- commit、push、PR作成指示が含まれていること。
- Issue/PRコメント投稿指示が最後段に含まれていること。
- コメントおよび補足結果ファイルに機密情報を含めない注意があること。
- 後続TSKへの越境禁止が明記されていること。
- ファイル化する場合は `CodexExec_<作業内容>.md` 形式になっていること。
