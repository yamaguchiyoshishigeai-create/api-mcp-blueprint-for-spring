# ローカル一時ファイルとルート直下整理方針

## 1. 目的

本書は、ChatExec / ChatExec2 / Codex 連携作業によってリポジトリルートに一時ファイル、実行結果、投入用指示書、補助ログが残り、Sourcetree 等のGUI上で未追跡ノイズとして表示され続ける問題を防ぐための横断運用規程である。

APIM for Spring では、ローカル精査により `ChatExec2_CleanupMergedBranches_APIM.result` が未追跡ファイルとして残っていることを確認した。この種のファイルは作業証跡として一時的には有用だが、リポジトリ成果物ではないため、Git履歴へ含めない。

## 2. 基本方針

1. リポジトリルートは、プロジェクト入口、ビルド定義、README、起動プロンプト、ソース・docs・scripts 等の恒久成果物に限定する。
2. ChatExec / ChatExec2 / Codex のローカル実行結果は、原則としてGit管理対象外とする。
3. GitHub Issue / PR コメントに投稿する内容は、サニタイズ済みの要約に限定する。
4. ローカル詳細ログは、必要に応じて `%TEMP%/<JOB_ID>/` または `.chatexec2/<JOB_ID>/` に出力する。
5. リポジトリルート直下へ一時結果ファイルを出力した場合は、作業完了後に削除する。
6. 一時結果ファイルを削除できない、または削除前に残る可能性がある場合は、`.gitignore` で誤コミットを防止する。

## 3. ルート直下に置いてよいもの

ルート直下に恒久配置してよいものは、原則として以下に限定する。

- `README.md`
- `PROJECT_START_PROMPT.md`
- `pom.xml`
- `mvnw`
- `mvnw.cmd`
- `.gitignore`
- `.github/`
- `.mvn/`
- `docs/`
- `scripts/`
- `src/`
- `AI_REPO_RESULT.md` など、リポジトリ運用上の正本として明示された文書

## 4. ルート直下に残さないもの

以下は、原則としてルート直下に残さない。

- `ChatExec.result`
- `ChatExec2_*.result`
- `ChatExec2_*.summary.md`
- `ChatExec2_*.log`
- `ChatExec2_*.out`
- `ChatExec2_*.err`
- `CodexExec.result`
- `CodexExec_*.result`
- `ChatExec-*.out`
- `ChatExec-*.err`
- `CodexExec-*.out`
- `CodexExec-*.err`
- 単発投入用の `CodexExec_*.md`
- 一時ログ、検証ログ、ローカル環境依存の出力

## 5. Codex投入用Markdownの扱い

`CodexExec_*.md` は一律ignore対象にしない。

理由は、Codex投入用指示書の一部は、後続保守や作業証跡として `docs/00_プロジェクト管理/03_実装支援AI指示/` 配下に保存すべき正規文書となる場合があるためである。

運用は以下とする。

| 種別 | 扱い |
|---|---|
| 正規の実装支援AI指示書として残すもの | `docs/00_プロジェクト管理/03_実装支援AI指示/` 配下へ配置する |
| 単発投入用・再生成可能・保存不要なもの | 作業完了後にローカル削除する |
| ルート直下に一時配置されたもの | 残すか削除するかを判断し、残す場合はdocsへ移動する |

## 6. `.gitignore` 標準追加対象

ChatExec2方式を使用するリポジトリでは、原則として以下を `.gitignore` に含める。

```gitignore
# ChatExec2 local execution artifacts
ChatExec2_*.result
ChatExec2_*.summary.md
ChatExec2_*.log
ChatExec2_*.out
ChatExec2_*.err

# Codex task-local transient artifacts
CodexExec_*.result
```

`CodexExec_*.md` は、正規文書として保存する可能性があるため一律ignoreしない。

## 7. ChatExec2スクリプト作成時の注意

ChatExec2スクリプトを作成する場合、以下を優先する。

1. 対象リポジトリパスが既知の場合は、スクリプト内に固定値として埋め込む。
2. ユーザーにフォルダ選択を要求しない。
3. フォルダ選択は、固定パスが不明または複数候補があり自動判定できない場合の例外手段とする。
4. Windows `.cmd` では、ダブルクリック実行時に `[OK]` / `[FAIL]` を視認できるよう、結果末尾表示とウィンドウ保持を行う。
5. 詳細結果は `%TEMP%/<JOB_ID>/` または `.chatexec2/<JOB_ID>/` に出力する。
6. GitHubコメントにはサニタイズ済み要約のみを投稿する。
7. トークン、秘密情報、環境変数全文、不要な絶対パス、個人情報を出力しない。

## 8. ローカルcleanupの扱い

`.gitignore` 更新は、今後の誤コミットを防ぐための対策であり、既にローカルに存在する一時ファイルを自動削除するものではない。

既存の一時ファイルは、必要に応じてChatExec2方式またはユーザー手作業で削除する。

削除対象の例:

- `ChatExec.result`
- `ChatExec2_*.result`
- 不要になった単発投入用 `CodexExec_*.md`

ただし、正規文書として保存すべき `CodexExec_*.md` を削除してはならない。保存する場合は、docs配下へ移動したうえでコミット対象にする。

## 9. 横展開方針

本方針は、APIM for Spring で有効性を確認したうえで、以下のリポジトリへ横展開候補とする。

- `Spring-Tool-Development-Template`
- `Q-Scout-for-Spring`
- `portfolio`

特に `Spring-Tool-Development-Template` へ反映する場合、今後作成されるSpring系ツールリポジトリの標準 `.gitignore` と運用文書へ波及させることを目的とする。

## 10. 完了条件

本方針の適用完了条件は以下である。

1. `.gitignore` にChatExec2結果ファイルのignoreパターンが追加されている。
2. `CodexExec_*.result` がignore対象になっている。
3. `CodexExec_*.md` を一律ignoreしない理由が文書化されている。
4. ルート直下に残してよいもの、残さないものの分類が明確である。
5. ChatExec2スクリプトでは、既知のリポジトリパスを固定値として埋め込み、不要なフォルダ選択を要求しない方針が明確である。
6. 既存ローカル一時ファイルの削除は、別途ローカルcleanupとして扱う。
