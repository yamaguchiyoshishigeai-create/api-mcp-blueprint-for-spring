# AIリポジトリ作業証跡管理ルール

## 目的

AI実行の透明性を確保し、作業結果を追跡可能にする。

## 記録対象

- 作業日時
- 作業ブランチ
- 作成・更新ファイル一覧
- 実施検証と結果
- 未実施検証と理由
- 残課題
- PR URL

## 記録ファイル

- 既定: `AI_REPO_RESULT.md`
- Codex詳細補足: `CodexExec_<作業内容>.result`（Issue/PRコメントだけでは不足する場合）

`CodexExec.result` のような固定名は、複数作業や再実行時に上書き・混同を招くため、今後の新規作業では標準としない。

Codexの主な実行結果、変更ファイル、commit SHA、PR番号、テスト結果、CI状況、次アクションは、原則としてGitHub IssueまたはPull Requestコメントへサニタイズ済み要約として記録する。

`CodexExec_<作業内容>.result` は、コメントには収まらない補足説明、追加検証結果、失敗時の切り分けメモなどが必要な場合のみ使用する。

`CodexExec_<作業内容>.result` には、APIキー、アクセストークン、`.env`、秘密鍵、フル環境変数、個人情報、不要な絶対パス、長大な生ログ全文を含めてはならない。

## セキュリティ必須観点

- 認証
- 認可
- 承認
- 人間確認
- 監査ログ

これらの観点を除外した要件・設計は受け入れない。
