# AI作業分担方針

## 1. 目的

本方針は、ユーザー、ChatGPT、Codex、Gemini、GitHub Copilot等のAI支援ツールの作業分担を明確化し、実装タスクを安全かつ小さな単位で進めるための横断運用規程である。

特に、実装支援AIの利用が推奨されるタスクであっても、いきなり実装支援AIへ丸投げせず、先にChatGPTが実装境界、スコープ、完了条件、後続タスクとの切り分けを整理することを目的とする。

## 2. 作業分類

本プロジェクトでは、作業主体を以下の4分類で扱う。

| 分類 | 位置づけ |
|---|---|
| ユーザー(人) | 最終意思決定者、手動操作、外部確認、主観判断を担当する。 |
| ChatGPT(会話内) | 会話内で完結する整理、比較、レビュー、設計、方針検討、指示書作成を担当する。 |
| ChatGPT(リポジトリ編集) | リポジトリへの直接変更を伴う小〜中規模のdocs更新、課題管理更新、局所差分、足場整備を担当する。 |
| 実装支援AI | Codex、Gemini、GitHub Copilot等を含み、実装、複数ファイル変更、テスト実行、ビルド検証、反復修正を担当する。 |

Codexは現時点で標準的に利用する実装支援AIの代表例として扱う。ただし、本方針はCodex固有の運用規程ではなく、将来的にGemini、GitHub Copilot、その他の実装支援AIを併用または置き換え利用する場合にも適用する。

## 3. ユーザー(人)の担当範囲

ユーザー(人)は、以下を担当する。

- 最終的な方針承認。
- 主観判断を伴う仕様・UX・優先順位の判断。
- ローカル環境、GUI、外部サービスなどAIが直接操作できない領域の確認。
- ChatExec2等のローカル実行スクリプトの実行。
- AIが提示した結果に対する確認、停止、方針変更の指示。

## 4. ChatGPT(会話内)の担当範囲

ChatGPT(会話内)は、会話内で完結する以下の作業を担当する。

- 要件整理。
- 課題整理。
- 方針比較。
- 設計境界定義。
- 「今回やること／やらないこと」の明文化。
- 後続TSKへ残す作業の整理。
- 実装支援AI向け指示書の作成。
- レビュー観点、完了条件、テスト条件の整理。

ChatGPT(会話内)は、リポジトリ状態を変更しない。リポジトリへの直接反映が必要な場合は、ChatGPT(リポジトリ編集)または実装支援AIの担当候補として再分類する。

## 5. ChatGPT(リポジトリ編集)の担当範囲

ChatGPT(リポジトリ編集)は、リポジトリへ直接変更を加えるが、原則として小〜中規模かつ局所的な差分を担当する。

主な担当範囲は以下である。

- README、docs、設計書、運用規程の更新。
- 改善タスク課題一覧、個別TSKファイル等の課題管理更新。
- 既存内容を完全取得できたファイルへの小〜中規模編集。
- 実装前の足場整備。
- 実装支援AIへ渡す前のスコープ境界、作業手順、完了条件の文書化。
- PR作成、CI確認、docs PRのmerge、merge後ブランチ整理案内。

ただし、以下の条件に該当する場合は、ChatGPT(リポジトリ編集)単独で進めず、実装支援AIまたはChatExec2によるローカル確認を優先する。

- 複数ファイルにまたがる実装変更。
- テスト実行やビルド検証が必須の変更。
- 既存ファイルが長大で、完全取得できない変更。
- 構造複雑度が高い変更。
- 反復修正が必要になりやすい変更。

## 6. 実装支援AIの担当範囲

実装支援AIは、実装と検証を中心に担当する。

主な担当範囲は以下である。

- Java、TypeScript、HTML、設定ファイル等の実装変更。
- 複数ファイルにまたがる変更。
- テスト追加・修正。
- Maven、Gradle、npm等のテスト実行。
- ビルド検証。
- CI失敗時の原因調査と反復修正。
- 大規模または構造的な改修。

実装支援AIへ作業を渡す場合は、可能な限りChatGPTが先に以下を整理する。

- 実装対象。
- 実装対象外。
- 後方互換条件。
- 後続TSKへ残す事項。
- 完了条件。
- 実行すべきテスト。

## 7. 実装支援AI推奨時の優先検討ルール

実装支援AIの利用が推奨されるタスクであっても、いきなり丸投げしてはならない。

まず、以下の順に分割可能性を検討する。

1. ChatGPT(会話内)で、実装境界・スコープ・完了条件を定義できるか。
2. ChatGPT(リポジトリ編集)で、docs、課題管理、作業指示書、足場整備を先に切り出せるか。
3. 実装支援AIへ渡す作業を、最小実装単位へ制限できるか。
4. 実装支援AIの実装範囲が後続TSKへ越境しないように指示できるか。

この検討を行ったうえで、実装・テスト・反復修正が必要な部分を実装支援AIへ渡す。

## 8. ChatGPT(リポジトリ編集)+実装支援AI最小実装方式

影響範囲が広いタスクでは、以下の分担方式を標準優先案として検討する。

| フェーズ | 担当 | 内容 |
|---|---|---|
| 1. 境界定義 | ChatGPT(会話内) | 今回やること、やらないこと、後続TSKへ残すこと、完了条件を整理する。 |
| 2. 足場整備 | ChatGPT(リポジトリ編集) | docs、課題管理、実装支援AI向け指示書、小規模な準備差分を整備する。 |
| 3. 最小実装 | 実装支援AI | 指示書で制限された範囲だけを実装し、テストを実行する。 |
| 4. 結果確認 | ChatGPT(会話内) / ChatGPT(リポジトリ編集) | PR内容、CI、完了条件、タスク境界逸脱有無を確認する。 |
| 5. 最終判断 | ユーザー(人) | 主観判断、merge方針、次作業方針を承認する。 |

この方式では、実装支援AIは「最小実装単位」を担当し、ChatGPTはその前段で作業境界と指示条件を明確化する。

## 9. 適用優先条件

以下のいずれかに該当する場合は、ChatGPT(リポジトリ編集)+実装支援AI最小実装方式を優先検討する。

- 影響範囲が広い。
- 後続TSKとの境界が曖昧である。
- 複数ファイル変更が予想される。
- テスト実行が必要である。
- ビルド検証が必要である。
- 既存仕様との後方互換を維持する必要がある。
- 事前にスコープ整理すれば実装を小さく切れる。

## 10. 非推奨事項

以下は非推奨とする。

- 境界未定義のまま実装支援AIへ丸投げする。
- 1つのTSKで後続TSKの実装まで進める。
- 「今回やらないこと」を定義せずに実装を始める。
- 完了条件を定義せずに実装を始める。
- 実装支援AIへ複数タスクを一括で渡し、レビュー不能な大差分を作る。
- ChatGPT(リポジトリ編集)が、完全取得できない長大ファイルや複雑な実装を単独で直接編集する。

## 11. TSK分割・越境防止方針

連続するTSK群では、各TSKの責務境界を明確にする。

特に以下を明示する。

- 当該TSKで実施すること。
- 当該TSKで実施しないこと。
- 後続TSKへ残すこと。
- 既存互換を維持する条件。
- 最小実装単位。
- 完了条件。

この方針により、TSK単位のPRを小さく保ち、レビュー容易性、CI失敗時の切り分け容易性、作業再開性を高める。

## 12. Codexプロンプト作成時の必須事項

ChatGPTがCodex等の実装支援AI向けプロンプトを作成する場合は、実装内容だけでなく、以下を必ず含める。

- 推奨モデル、推奨インテリジェンス、推奨速度、および推奨理由。
- 実装後のcommit手順。
- remote branchへのpush手順。
- Pull Request作成手順。
- Pull Request本文に記載すべき項目。
- ChatExec2方式に準じたIssue/PRコメントでの実行状況引き継ぎテンプレート。
- 機密情報、長大ログ全文、不要な絶対パスをIssue/PRコメントへ投稿しない注意。

これにより、実装支援AIの作業がローカル差分で停止すること、PR化されないこと、後続ChatGPTが実行状況を把握できないことを防止する。

## 13. Issue/PRコメントによる引き継ぎ方針

実装支援AIに作業を渡すプロンプトの最後段には、IssueまたはPull Requestコメントへ投稿する実行状況サマリを含める。

コメントには、少なくとも以下を含める。

- JOB_ID。
- STATUS。
- 対象リポジトリ。
- 対象ブランチ。
- commit SHA。
- 実行した主なコマンド。
- 変更ファイル一覧。
- テスト結果サマリ。
- CI結果サマリ。
- 次に必要な判断事項。
- 実行開始時刻と終了時刻。

詳細は `docs/00_プロジェクト管理/05_横断運用規程/Codexプロンプト運用方針.md` を正とする。

## 14. 完了条件

本方針に従う作業では、少なくとも以下を完了条件として検討する。

- 実装境界が明文化されている。
- やること／やらないことが明文化されている。
- 後続TSKへ残す事項が明文化されている。
- 実装支援AIへ渡す最小実装単位が明文化されている。
- テスト条件が明文化されている。
- 既存互換条件が明文化されている。
- Codex等へ渡すプロンプトに、推奨設定、commit、push、PR作成、Issue/PRコメント引き継ぎが含まれている。
