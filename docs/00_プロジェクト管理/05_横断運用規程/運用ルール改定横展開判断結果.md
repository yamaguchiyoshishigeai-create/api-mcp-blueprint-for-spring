# 運用ルール改定横展開判断結果

## 1. 目的

本書は、APIM for Springで追加・明文化された以下の運用ルールについて、関連リポジトリへの横展開要否を判断した結果を記録する。

対象ルールは以下である。

1. TSK-047: ローカル一時ファイルとルート直下整理方針。
2. TSK-048: CIポーリング終了条件固定方針。
3. TSK-050: Merge後cleanup・local sync自動統合方針。

本書は横展開の実施そのものではなく、横展開要否、適用粒度、後続タスク分割方針を定める判断記録である。

## 2. 調査対象

横展開候補は以下の3リポジトリである。

| リポジトリ | 用途 | 既存横展開状況 |
|---|---|---|
| `Spring-Tool-Development-Template` | Spring系派生ツール開発テンプレート | PR #31で運用ルールHubとCodex投入ゲートを横展開済み |
| `Q-Scout-for-Spring` | Spring系実装対象プロダクト | PR #90で運用ルールHubとCodex投入ゲートを横展開済み |
| `portfolio` | 公開ポートフォリオ | PR #14で軽量版運用ルールHubとCodex投入ゲートを横展開済み |

## 3. 調査結果

### 3.1 Spring-Tool-Development-Template

`Spring-Tool-Development-Template` には、運用ルールHub系の文書が存在する。

確認できた代表例は以下である。

- `docs/00_プロジェクト管理/05_横断運用規程/00_運用ルール索引と実行ゲート.md`
- `docs/00_プロジェクト管理/05_横断運用規程/Codex指示書テンプレート.md`

また、PR #31でAPIM側の運用ルールHubとCodex投入ゲート標準化が横展開済みである。

一方、TSK-047 / TSK-048 / TSK-050で追加した3規程名の完全一致は確認できなかった。

### 3.2 Q-Scout-for-Spring

`Q-Scout-for-Spring` には、運用ルールHub系の文書が存在する。

確認できた代表例は以下である。

- `docs/00_プロジェクト管理/05_横断運用規程/00_運用ルール索引と実行ゲート.md`
- `docs/00_プロジェクト管理/05_横断運用規程/Codex投入前ハンドオフゲート方針.md`
- `docs/00_プロジェクト管理/05_横断運用規程/Codex指示書テンプレート.md`

また、PR #90でAPIM側の運用ルールHubとCodex投入ゲート標準化が横展開済みである。

一方、TSK-047 / TSK-048 / TSK-050で追加した3規程名の完全一致は確認できなかった。

### 3.3 portfolio

`portfolio` は公開ポートフォリオ用リポジトリであり、PR #14で軽量版の運用ルールHubとCodex投入ゲートが横展開済みである。

ただし、検索上はAPIMやSpring系リポジトリと同じ横断運用規程ファイル名が完全一致では確認できなかった。portfolioでは公開安全性条件を優先する軽量版として扱う必要がある。

TSK-047 / TSK-048 / TSK-050で追加した3規程名の完全一致も確認できなかった。

## 4. 判断結果

| リポジトリ | 判断 | 理由 | 後続方針 |
|---|---|---|---|
| `Spring-Tool-Development-Template` | 部分反映 | ChatExec2、Codex、CI、branch cleanupをテンプレート運用でも使うため有用。ただしテンプレートであり、APIM固有のルート直下ファイル名やTSK例をそのままコピーすべきではない。 | 後続タスクでテンプレート向けにTSK-047 / TSK-048 / TSK-050相当を抽象化して反映する。 |
| `Q-Scout-for-Spring` | 部分反映 | Spring系プロダクトであり、APIMと同様にChatExec2、Codex、CI、branch cleanupの運用が発生するため有用。既存Hubとの整合を取りつつ反映すべき。 | 後続タスクでQ-Scout向けにTSK-047 / TSK-048 / TSK-050相当を反映する。 |
| `portfolio` | 部分反映 | 公開ポートフォリオ用のため軽量版が妥当。CIやbranch cleanupの考え方は有用だが、公開安全性条件と衝突しないよう簡略化すべき。 | 後続タスクでportfolio向け軽量版として必要部分のみ反映する。 |

## 5. 即時横展開しない理由

本判断では、3リポジトリとも `部分反映` とするが、TSK-053内では即時横展開を行わない。

理由は以下である。

1. 3リポジトリで既存運用規程の構成が異なる。
2. `Spring-Tool-Development-Template` はテンプレートであり、APIM固有例を抽象化する必要がある。
3. `Q-Scout-for-Spring` は実プロダクトであり、既存Q-Scout運用規程との整合確認が必要である。
4. `portfolio` は公開安全性条件が強く、軽量版として記述量と公開情報の範囲を調整する必要がある。
5. 無条件コピーは、運用規程の重複、過剰記述、公開リポジトリへの不要情報混入につながる。

## 6. 後続タスク分割方針

TSK-053の完了後、必要に応じて以下の後続タスクとして分割する。

| 後続ID案 | 件名 | 対象 |
|---|---|---|
| TSK-054 | Spring-Tool-Development-TemplateへTSK-047/048/050系運用ルールを部分横展開する | `Spring-Tool-Development-Template` |
| TSK-055 | Q-Scout-for-SpringへTSK-047/048/050系運用ルールを部分横展開する | `Q-Scout-for-Spring` |
| TSK-056 | portfolioへTSK-047/048/050系運用ルールを軽量横展開する | `portfolio` |

後続IDは、実際に着手する時点で課題一覧の最新状態を確認して確定する。

## 7. 完了判定

TSK-053は、以下を満たした時点で完了とする。

1. 横展開候補3リポジトリの既存運用規程状況を確認している。
2. 各リポジトリについて、即時反映、部分反映、保留、不要のいずれかを判断している。
3. 判断結果を本書に記録している。
4. 必要な横展開は後続タスクへ分割する方針を明記している。
5. TSK-053個票と課題一覧を解決済みへ同期している。
